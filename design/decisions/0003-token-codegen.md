# DSN-ADR-0003. Генерация кода токенов: свой генератор вместо Style Dictionary

- **Статус:** принято мейнтейнером (ADR-0011 делегирует дизайн-решения); владелец может пересмотреть.
- **Дата:** 2026-11-14
- **Задача:** DSN-003 (`docs/ROADMAP.md`)
- **Ссылки:** `docs/research/01-product-ux-design.md` §5.2; `design/tokens/README.md`; DSN-ADR-0001.

## Контекст

Токены лежат в `design/tokens/` в формате DTCG 2025.10: цвета — объекты `{colorSpace, components, alpha, hex}`, размеры и длительности — `{value, unit}`, составные типы (shadow, gradient, transition, typography) со ссылками внутри. Нужен код для четырёх платформ — Dart (`pa_design`, API уже используется приложением релиза 0.1), Swift (tvOS/iOS), Kotlin (нативный Android) и CSS (веб-админки, сайт) — и CI-проверка, что сгенерированное совпадает с JSON.

В репозитории уже есть всё, что нужно для резолва: `scripts/lib/dtcg.mjs` (валидатор, резолвер ссылок, проверка контраста) без зависимостей. Тема и плотность — две независимые оси (2 × 4 комбинации); код каждой платформы должен иметь одинаковую форму: константы, схема цветов по темам, профиль плотности.

## Варианты

| Критерий | Style Dictionary 4/5 | Свой генератор на `dtcg.mjs` |
|---|---|---|
| Объектные значения DTCG 2025.10 | Встроенные трансформы рассчитаны на строковые значения (`#rrggbb`, `16px`); объектные цвета и размеры нужно переводить своими трансформами | Читает ровно наш формат; валидатор и генератор используют один резолвер |
| Раскладка тема × плотность в типы `PaColorScheme` / `PaDensity` | Нет: один прогон — одна комбинация; классификацию токенов по осям и классы пришлось бы писать своими форматами | Встроена в модель (`lib/tokens-model.mjs`) |
| Объём своего кода | Трансформы + 4 формата + конфиг ≈ столько же, сколько сам генератор | ≈ 450 строк на 4 платформы |
| Зависимости | npm-пакет и его дерево (MIT/Apache), обновления, `postinstall` | Нет; работает до `npm ci` |
| Воспроизводимость | Зависит от версии пакета и трансформов | Вывод зависит только от JSON и кода в репозитории |
| Готовые форматы (Compose, SwiftUI, CSS) | Есть, но с другим API и без наших составных типов | Пишем сами, под API, совпадающий на всех платформах |

## Решение

1. **Свой генератор без зависимостей** — «эквивалент Style Dictionary», который ROADMAP допускает: `scripts/tokens-build.mjs` → общая модель `scripts/lib/tokens-model.mjs` → эмиттеры `scripts/lib/emit-{dart,swift,kotlin,css}.mjs`. Версия генератора закреплена самим репозиторием; вывод побайтно воспроизводим.
2. **Одинаковая форма на всех платформах:** `PaTokens` (константы), `PaColorScheme.dark|light`, `PaDensity.tv|desktop|tablet|phone`; имена — путь токена в camelCase. Токен, зависящий и от темы, и от плотности, — ошибка генерации (его нужно разделить). API Dart-пакета `pa_design` не изменился.
3. **Куда пишется:** Dart — в пакет `pa_design`; Swift, Kotlin, CSS — в `design/tokens/generated/{apple,android,web}/`. Клиенты подключают файл по пути (TVApp — через `project.yml`, как `PaIcon.swift`), руками ничего не копируют.
4. **Маппинг по платформам:** Apple — SwiftUI-типы, шрифт Inter заменяется системным (DSN-ADR-0002); Android — без зависимостей (ARGB `Int`, `Float`), чтобы файл подключался и к View, и к Compose; CSS — custom properties, тема и плотность переключаются `data-theme` / `data-density`.
5. **CI-гейт** — в существующем workflow `Design` (`npm run check`): `tokens:check` сравнивает все четыре файла с заново сгенерированными; контраст проверяет `tokens:validate`, минимум ниже 4.5:1 требует обоснования (`note`) и не может быть ниже 3:1.

## Последствия

- **Плюсы:** ноль зависимостей и сетевых загрузок в CI; один резолвер для проверки и генерации; общий API на всех платформах; PR с изменением токена показывает дифф во всех файлах.
- **Минусы:** форматы под новую платформу (например, XML-ресурсы Android, Tailwind) пишем сами; нет экосистемы плагинов Style Dictionary.
- **Если понадобится Style Dictionary** (например, для импорта из Penpot или Tokens Studio): JSON уже в DTCG, поэтому переход затронет только `scripts/`; критерий — сгенерированные файлы совпадают с текущими или дифф осознанно принят.
