## 1. Пирамида и уровни тестов

| Уровень | Что проверяет | Где живёт | Скорость | Когда |
|---|---|---|---|---|
| **Unit** | Чистая логика: парсер имён, модель, HLC/LWW, расписания, форматирование | рядом с кодом: `#[cfg(test)]`, `test/` пакета Dart, `src/test` Kotlin, `Tests/` Swift | мс | каждый PR |
| **Property / fuzz** | Инварианты на случайных входах: парсеры имён, NFO, M3U/LRC, HLS, ответы SMB/WebDAV, сообщения sync | `proptest` в крейте; `fuzz/` (`cargo-fuzz`, QA-005) | с–мин | PR (proptest), ночью (fuzz) |
| **Интеграционные** | Крейт целиком с реальными зависимостями: SQLite и миграции, `pa-probe` на файлах из `tests/media`, WebDAV/SMB-серверы в Docker | `core/crates/*/tests/`, `server/tests/` | с | каждый PR (тяжёлые — при изменении путей) |
| **Контрактные** | Границы между частями: FFI (FRB/UniFFI) ↔ Dart/Swift, OpenAPI сервера, протокол sync ±1 версия, API `pa_library`/`pa_player` (релиз 0.1) | `tests/contract/`, тесты пакетов | с | каждый PR, если затронута граница |
| **Widget / UI** | Экраны Flutter с моками ядра; фокус и D-pad на TV | `clients/flutter/**/test/` | с | каждый PR |
| **Golden** | Пиксельная регрессия ключевых экранов и компонентов ([§5](#5-golden-тесты-визуальная-регрессия)) | `test/goldens/` пакета | с | каждый PR |
| **E2E** | Сценарий пользователя: онбординг → источник WebDAV из docker-compose → скан → Detail → воспроизведение (mock-движок) → «Продолжить» (QA-004) | `clients/flutter/integration_test/`, `tests/e2e/` | мин | PR в `clients/flutter` + ночью |
| **Матрица воспроизведения** | «файлы × платформы × движки»: открыть, 10 с, seek, смена дорожки (QA-003) | `tests/playback/` | мин | ночью и перед релизом |
| **Производительность** | Бюджеты: сетка 10 000 элементов 60 fps, холодный старт < 2 с, скан 10 000 файлов < 60 с (QA-006, M1) | `benches/`, профили Flutter | мин | ночью; регрессия > 20 % помечает PR |
| **Сеть** | netem: задержка, потери, полоса; плеер не буферизует при запасе 2× (QA-007) | `tests/network/` | мин | ночью |
| **Ручные** | HDR, DV, passthrough, AFR, пульты, ресиверы, доступность ([§7](#7-device-lab-и-ручные-чек-листы)) | `docs/dev/checklists/` | ч | перед релизом |

Правило выбора уровня: тест пишется на **самом низком уровне, где ошибка видна**. Баг
распознавания имени — unit-тест парсера, а не e2e. E2E покрывает только связки, которые
нельзя проверить иначе.

### 1.1. Что считается «тестом на баг»

Каждый исправленный баг получает регрессионный тест того уровня, где он воспроизводится.
Если воспроизвести можно только на устройстве — пункт в ручном чек-листе с ссылкой на issue.
Падения из фаззинга сохраняются как фикстуры и становятся обычными тестами (QA-005).

## 2. Что обязательно в каждом PR

Минимум, без которого PR не мержится (дополняет Definition of Done из [ROADMAP §0.3](../ROADMAP.md)):

1. **Новая логика покрыта тестами** уровня unit или интеграционного. Исключения: чистый UI
   без логики (тогда widget- или golden-тест), скрипты сборки (тогда проверка в CI), документация.
2. **Исправление бага** — с регрессионным тестом (§1.1).
3. **Зелёный CI** во всех затронутых джобах (§6): форматирование, линтеры, тесты.
4. **Изменён контракт** (FFI, OpenAPI, протокол sync, схема БД, API пакетов 0.1) — обновлены
   контрактные тесты и, если нужно, миграция с тестом «вверх» на копии реальной схемы.
5. **Изменён экран** — обновлены golden-файлы, а в описании PR приложены картинки «было/стало».
6. **Платформенные `done when`** — в описании PR перечислено, где проверено: эмулятор,
   симулятор, устройство (модель, версия ОС). «Не проверено на устройстве» — тоже ответ, тогда
   пункт попадает в ручной чек-лист релиза.
7. **Тестовые данные** — только синтетические или под свободной лицензией, через манифест
   [`tests/media/manifest.toml`](../../tests/media/manifest.toml); никаких личных файлов, путей и
   ключей API в фикстурах.
8. **Без сети в unit- и интеграционных тестах.** Внешние сервисы (TMDB, Twitch, OpenSubtitles)
   — через записанные ответы (фикстуры JSON) или локальный мок-сервер. Живые запросы — только в
   отдельных ночных smoke-тестах с ключами из GitHub Secrets.

Чего от PR **не** требуем: процент покрытия. Покрытие (`cargo llvm-cov`, `flutter test --coverage`)
считается и публикуется как информация, но порога нет — порог провоцирует бесполезные тесты.

## 3. Инструменты и команды по языкам

| Язык / часть | Тесты | Линтеры | Команда |
|---|---|---|---|
| Rust (`core/`, `server/`, `tools/crates/`) | `cargo nextest`, doc-тесты `cargo test --doc`, `proptest`, `insta` для снапшотов, `cargo-fuzz` | `cargo fmt`, `clippy -D warnings`, `cargo deny` | `cargo nextest run --workspace` (CI-001: `.github/workflows/rust.yml`) |
| Dart / Flutter (`clients/flutter/`) | `flutter test` (unit, widget, golden), `integration_test` | `dart format`, `flutter analyze` | `flutter test` |
| Kotlin (`clients/android/`) | JUnit 5, Robolectric; instrumented на эмуляторе (`connectedCheck`) | ktlint, Android Lint | `./gradlew test` |
| Swift (`clients/apple/`) | XCTest / Swift Testing на симуляторах iOS и tvOS | SwiftLint | `xcodebuild test` |
| Go (`distro/`) | `go test ./...` | `go vet`, `staticcheck` | `go test ./...` |
| Python-инструменты (`tools/`, `docs/dev/scripts/`) | `unittest` | — | например `just tests::media-selftest` |

Рецепты `just <область>::test` появляются в justfile своей области вместе с первым кодом
(правило §0.5 ROADMAP); пока их нет, используйте команду инструмента напрямую.

Соглашения:

- Имена тестов описывают поведение: `parses_anime_absolute_episode`, а не `test1`.
- Таймзона, локаль и время фиксируются в тестах (`TZ=UTC`, фиктивные часы) — иначе тесты
  ломаются на машинах контрибьюторов в других поясах.
- Тесты не пишут за пределы временного каталога и не зависят от порядка запуска.
- Для снапшотов (`insta`, golden) изменение эталона — осознанное действие в отдельном коммите
  с пояснением.

## 4. Тестовые данные

- **Медиафайлы** — [`tests/media/`](../../tests/media/README.md) (QA-002): генератор
  синтетического набора, манифест с ожидаемыми свойствами каждого файла и список реальных
  файлов под свободными лицензиями (Blender Open Movies). Бинарники в git не хранятся.
  Тесты ищут файлы по `id` из манифеста и **пропускаются** с сообщением `run: just tests::media`,
  если набор не сгенерирован.
- **Фейковая медиатека** — `just tests::media-library`: дерево фильмов, сериалов, аниме и музыки
  с реалистичными именами для скриншотов, демо и тестов сканера (релиз 0.1).
- **Корпус распознавания** — `tools/recognition-eval/` (META-001, META-003): имена файлов и
  ожидаемые сопоставления; качество распознавания меряется отдельно от unit-тестов.
- **Ответы сервисов** — записанные JSON в `tests/fixtures/<сервис>/` с удалёнными ключами;
  обновляются скриптом, а не руками.
- **Сетевые источники** — `tests/docker/` (появится с NET-задачами): Samba, WebDAV (nginx/rclone),
  NFS, Jellyfin — для интеграционных и e2e-тестов.

## 5. Golden-тесты (визуальная регрессия)

Цель — ловить случайные изменения внешнего вида ключевых экранов на всех платформах
(01 §4.10 п. 5). Референсная платформа — TV-раскладка.

- **Что снимаем:** Home, Detail фильма и сериала, сетка библиотеки, OSD плеера, Now Playing,
  настройки; компоненты дизайн-системы (карточка в фокусе и без, кнопки, чипы). Каждый экран — в
  профилях плотности TV / desktop / tablet / phone, тёмная тема, русский и английский, масштаб
  текста 100 % и 200 %.
- **Как:** `flutter test` с `matchesGoldenFile`; шрифты проекта загружаются в тесте явно
  (без системных), анимации выключены, изображения постеров — локальные фикстуры.
- **Где генерируются эталоны:** только в CI-образе Linux (одинаковый рендер шрифтов). Локально
  обновлять командой `flutter test --update-goldens` в том же контейнере; эталоны с macOS или
  Windows не коммитятся.
- **Допуск:** 0 различающихся пикселей по умолчанию; для экранов с размытием (glass) — допуск
  через собственный `GoldenFileComparator` до 0,5 % пикселей, с комментарием в тесте.
- **Нативные экраны** (SwiftUI на tvOS, Kotlin-компоненты) — снапшот-тесты своих платформ
  (swift-snapshot-testing, Paparazzi), по тем же правилам.
- **Ревью:** при изменении golden-файлов CI прикладывает к PR дифф картинок (артефакт джоба).

## 6. CI: что и когда запускается

| Событие | Что запускается |
|---|---|
| Каждый PR | DCO; Rust: fmt, clippy, nextest (только при изменении Rust, `rust.yml`); Flutter: analyze, unit, widget, golden (при изменении `clients/flutter`); docs: актуальность сгенерированных документов (`docs.yml`); юнит-тесты инструментов QA (`test-media.yml`) |
| PR, затрагивающий платформу | сборка этой платформы и её тесты (фильтры путей, как в 04 §4.4) |
| Push в `main` | всё из PR без фильтров путей |
| Ночью | генерация тестовых медиа + интеграционные тесты `pa-probe`, e2e, матрица воспроизведения, фаззинг 30 мин на цель, замеры производительности, smoke с живыми сервисами |
| Тег релиза | полный набор + сборки всех платформ; ручной чек-лист релиза (QA-008) подтверждает владелец |

Правила:

- Один обязательный статус на workflow (`all-green` в `rust.yml`), чтобы защита ветки не
  зависела от набора джобов.
- PR от форков запускаются без секретов; тесты, которым нужны ключи, пропускаются, а не падают.
- Ночные падения создают issue с меткой `ci-nightly` (CI-задачи), их разбирают до следующего релиза.

## 7. Device lab и ручные чек-листы

Автоматика не видит: включился ли на телевизоре HDR/DV, переключилась ли частота, что
показывает ресивер, как работает пульт. Это проверяется вручную на реальных устройствах.

**Устройства** (список и владельцы — `docs/dev/device-matrix.md`, задача QA-011): NVIDIA Shield,
Chromecast с Google TV, Fire TV, Apple TV 4K, HDR-телевизор с Dolby Vision, AV-ресивер с Atmos
и DTS:X, USB-DAC, мини-ПК Intel N100 (NAS), средний Android-телефон, ПК с HDR-монитором
(Windows 11, KDE Plasma 6), Mac.

**Чек-листы** — в `docs/dev/checklists/` (появляются вместе с задачами платформ), по одному на
область. Каждый пункт: шаги, файл из [`tests/media/manifest.toml`](../../tests/media/manifest.toml)
по `id`, ожидаемый результат. Шаблон пункта:

```markdown
- [ ] HDR10 → телевизор переходит в HDR10
  - файл: `hdr-hdr10-hevc-mkv`; устройство: Shield, ТВ с HDR
  - ожидаем: значок HDR10 на ТВ ≤ 2 с после старта; после выхода — SDR
```

| Чек-лист | Что входит | Когда |
|---|---|---|
| HDR и DV | HDR10, HDR10+, HLG, DV 5 / 8.1 / 8.4, тон-маппинг на SDR-экране (DV 5 без зелёно-фиолетовых цветов) | перед каждым релизом с изменениями плеера |
| Звук | passthrough AC-3 / E-AC-3 / TrueHD / DTS на ресивер, раскладка 5.1/7.1 по тонам каналов, gapless | то же |
| AFR | 23.976 / 24 / 25 / 29.97 / 50 / 59.94, возврат режима после выхода | то же |
| Ввод и TV | D-pad, фокус, «назад», пульты Shield / Apple TV / Fire TV, клавиатура и мышь на десктопе | каждый релиз |
| Доступность и локализация | TalkBack, VoiceOver, Narrator, Orca; 200 % текста; псевдолокализация (QA-009) | каждый минорный релиз |
| Релиз | миграции и откат, совместимость sync и API ±1, store-флейвор, лицензии, changelog (QA-008) | каждый релиз |

Результат прохода фиксируется в PR или issue релиза: версия, устройство, отмеченные пункты,
ссылки на найденные баги. Агенты готовят код и автотесты; проверку на устройстве закрывает
владелец устройства (ROADMAP §5).

## 8. Ответственные за платформы

Ответственный — тот, кто ревьюит тесты платформы, держит её джобы CI зелёными и проходит
её ручной чек-лист (или находит, кто пройдёт). Пока проект ведёт один мейнтейнер, все роли
у него (см. `.github/CODEOWNERS`); по мере появления контрибьюторов роли передаются и
записываются сюда и в `docs/dev/device-matrix.md`.

| Платформа / область | Автотесты | Устройства для ручной проверки | Ответственный |
|---|---|---|---|
| Rust-ядро, сервер | nextest, proptest, fuzz | — | мейнтейнер |
| Linux-десктоп | Flutter, golden, матрица воспроизведения | ПК с HDR (KDE Plasma 6), ресивер | мейнтейнер |
| Windows | Flutter, матрица воспроизведения | ПК с HDR (Windows 11), ресивер | вакантно → мейнтейнер |
| macOS | Flutter, XCTest | Mac | вакантно → мейнтейнер |
| Android, Android TV | JUnit, instrumented на эмуляторе, Flutter | Shield, Chromecast GTV, Fire TV, телефон | мейнтейнер |
| iOS, iPadOS, tvOS | XCTest на симуляторах | iPhone, Apple TV 4K | вакантно → мейнтейнер |
| NAS-дистрибутив | `go test`, тесты образа в VM | Intel N100 | вакантно → мейнтейнер |
| Тестовые данные, стратегия, CI-джобы QA | `tools/qa/` | — | workstream QA |

## 9. Нестабильные тесты, пропуски и долг

- **Flaky-тест** не перезапускают до зелёного: его помечают (`#[ignore = "flaky: #123"]`,
  `skip: 'flaky: #123'`), заводят issue с меткой `flaky` и чинят в течение недели. Больше двух
  помеченных тестов в области — повод остановить новые фичи в ней.
- **Пропуск по окружению** (нет FFmpeg, нет тестовых медиа, нет секрета) — явный, с сообщением,
  что запустить; молчаливое `return` в тесте запрещено.
- **Тайм-ауты:** unit-тест — до 1 с, интеграционный — до 30 с; дольше — переносится в ночной прогон.
- Временно отключённый ручной пункт чек-листа сопровождается issue и сроком.
