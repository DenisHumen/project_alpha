## 1. Продукт

Свободный (open source) медиаплеер уровня Infuse **на всех платформах** (Linux, macOS, Windows, iOS/iPadOS, Android/Android TV, Apple TV), с **заметно лучшим распознаванием** фильмов, сериалов и аниме, **Spotify-подобным музыкальным плеером** (любые форматы, gapless, bit-perfect), **удобным Twitch-клиентом** (эфиры с чатом, VOD, загрузки, архив) и **продолжением просмотра на любом устройстве**.

Принцип: **никаких серверов у нас**. Всё — на устройствах пользователя: клиент, его собственный медиасервер (любой ПК/Docker или наш NAS-дистрибутив), его SMB/NFS-папки. Обращения наружу — только напрямую к публичным сервисам (TMDB, AniList, Twitch и т. п.) с устройства пользователя.

Режимы (одинаково полноценные):
- **A. «Только приложение»** — указал SMB/NFS/WebDAV-папку, приложение само сканирует и строит медиатеку.
- **B. «Свой сервер»** — наш сервер на ПК/NAS индексирует, качает метаданные, транскодирует, записывает Twitch, хранит общую медиатеку и **синхронизирует прогресс** между устройствами.
- **C. Совместимость** с Plex / Jellyfin / Emby.

Навигация: **Главная · Фильмы · Сериалы · Twitch · Музыка · Поиск**. Единый ряд «Продолжить» для фильмов, серий и Twitch-VOD.

## 2. Синхронизация без нашего облака

Мгновенное продолжение на другом устройстве остаётся обязательным. Решение — **хабом синхронизации становится то, что у пользователя уже есть**:

| Ситуация | Как синхронизируется |
|---|---|
| Есть наш сервер (режим B) | Сервер = хаб. Протокол из исследования 04 §1.8: WebSocket, heartbeat 5 с + сразу на паузе/перемотке, HLC, офлайн-очередь. Баннер «Продолжить здесь». |
| Только приложения, все в одной сети (режим A) | **P2P между устройствами в LAN**: обнаружение через mDNS, обмен тем же протоколом напрямую; любое включённое устройство — хаб. |
| Только приложения, вне дома | Файл состояния в **той же SMB/WebDAV-папке** (`.project_alpha/state/*.jsonl`, append-only журнал на устройство + слияние по HLC) — синхронизация «через хранилище», без сервера. |
| Удалённый доступ к своему серверу | **iroh** (QUIC + пробивка NAT) с **публичными relay от n0 или relay, поднятым пользователем** (встроен в сервер/дистрибутив); альтернативно — Tailscale/WireGuard пользователя. |
| Опционально | Интеграция с **Trakt** (аккаунт пользователя) — история просмотров. |

Ключи элементов единые: файл по хэшу/ID медиатеки, Twitch VOD — `twitch:vod:<id>` (онлайн и скачанный — один ключ).

## 3. Ключевые технические решения

| Область | Решение |
|---|---|
| Общее ядро | **Rust**: сеть (SMB/NFS/WebDAV), клиенты Plex/Jellyfin/Emby, медиатека SQLite, распознавание, синхронизация, Twitch Helix. Привязки UniFFI (Swift/Kotlin), flutter_rust_bridge |
| UI | **Flutter** для Android, Android TV, iOS/iPadOS, Windows, Linux, macOS; **SwiftUI** для Apple TV |
| Экран плеера | Всегда нативный: HDR/DV, смена частоты кадров, passthrough |
| Движок видео | Android: Media3/ExoPlayer (+libass); Apple: MPVKit/AVPlayer → свой FFmpeg+VideoToolbox; десктоп: libmpv (gpu-next) |
| Музыка | libmpv-аудио → свой Rust-движок (bit-perfect, DSD через DoP) |
| Распознавание | Папка целиком, многосигнально, N-best с уверенностью, маппинг AniDB↔TVDB↔TMDB (открытые таблицы anime-lists — **встраиваем в приложение и обновляем с GitHub**), ed2k-хэш для AniDB. LLM — **только локальная модель** или ключ API пользователя |
| Метаданные | Запросы **напрямую с устройства/сервера пользователя**: TMDB (рус. переводы), AniList, Shikimori, AniDB (аккаунт пользователя), MusicBrainz, LRCLIB. Ключ проекта по умолчанию + поле «свой ключ» |
| Медиасервер | Один Rust-бинарь (axum), SQLite WAL, FFmpeg с HW-ускорением, direct play → remux → HLS, REST+WS, mDNS. Он же хаб синхронизации и очередь задач (сканы, транскод, загрузки и запись Twitch) |
| Дистрибутив | Образ Fedora bootc в GHCR (cosign), свой установщик на Go (2 экрана, имена дисков «Samsung 990 PRO 1TB — /dev/nvme0n1»), RAID-мастер, атомарные обновления с авто-откатом через веб/приложение |
| Twitch | Helix через **Device Code Flow** прямо с устройства (публичный client_id, без секрета); уведомления — **EventSub WebSocket** или опрос `streams/followed` с сервера/приложения; видео через GQL+usher с удалённо обновляемым конфигом (файл в публичном репо) |

## 4. Деньги: пожертвования

- Площадки: **GitHub Sponsors**, **Open Collective** (прозрачный бюджет; с фискальным хостом — шанс на статус некоммерческой организации), **Liberapay**, **Ko-fi**; для аудитории из СНГ — **Boosty**. Ссылки — на сайте, в README и в desktop/F-Droid-сборках («О программе»).
- **Сторы ограничивают ссылки на донаты:**
  - **App Store** запрещает внешние ссылки/кнопки на оплату в приложении; «чаевые» — только через In-App Purchase (Apple берёт 15–30 %), либо через статус одобренной некоммерческой организации ([обсуждение 1](https://developer.apple.com/forums/thread/791096), [2](https://developer.apple.com/forums/thread/114186), [кейс Insight Timer](https://www.macrumors.com/2024/02/21/insight-timer-ceo-app-store-dispute)).
  - **Google Play** удалял/отклонял open source-приложения за ссылки на донаты: WireGuard (2019), StreetComplete (2022), AnkiDroid ([The Register](https://www.theregister.com/2022/03/02/google_blocks_android_foss_donations/), [StreetComplete #3768](https://github.com/streetcomplete/StreetComplete/issues/3768)).
  - **Решение:** в сборках для App Store и Google Play — **либо без ссылок на донаты, либо «чаевые» через IAP** (необязательные consumable-покупки $1/$5/$10, ничего не открывают); во всех остальных сборках (GitHub, F-Droid, Flathub, AUR, winget, ISO) — прямые ссылки.
- Расходы проекта минимальны: нет облака. Остаются Apple Developer ($99/год), Google Play ($25 разово), домен/сайт (можно GitHub Pages), хостинг ISO (Cloudflare R2, бесплатный исходящий трафик), подпись Windows, при желании — GitHub Actions на macOS.

## 5. Open source: лицензия и что это меняет юридически

- **Лицензия кода: MPL-2.0** (рекомендация). Файловый копилефт: изменения наших файлов остаются открытыми, но лицензия **совместима с App Store** и с LGPL-библиотеками (FFmpeg/mpv), а также с GPL (MPL-2.0 допускает объединение с GPL). Альтернатива — GPL-3.0: сильнее защищает от закрытых форков, но **конфликтует с App Store** (история VLC), если в проекте есть код сторонних контрибьюторов без отдельного согласия. Для любого варианта — **DCO** (Signed-off-by) на коммиты.
- FFmpeg/mpv: в сборках для App Store — только LGPL и динамически; в desktop/F-Droid-сборках можно GPL-сборки FFmpeg, если итоговая лицензия бинаря это допускает.
- **Что open source и «всё локально» действительно упрощают:**
  - нет облака → нет хранения персональных данных, токенов, истории просмотров у нас (GDPR и т. п. практически не касается проекта);
  - нет продаж → нет НДС, merchant of record, юрисдикции продавца;
  - некоммерческий статус облегчает бесплатное использование TMDB/AniDB и др. (TMDB бесплатен для некоммерческого использования с атрибуцией — [FAQ](https://developer.themoviedb.org/docs/faq), [условия](https://themoviedb.org/api-terms-of-use)).
- **Что НЕ меняется (честно):**
  - ToS Twitch по-прежнему запрещает скачивание; ответственность смещается на пользователя, но **сторы всё равно удалят приложение** с этой функцией → в App Store/Play сборках загрузки Twitch выключены (код не вырезаем — он открыт, но сборка для сторов собирается с выключенным флагом).
  - Сторы считают коммерческим любое приложение в магазине; TMDB может трактовать донаты как коммерцию → **спросить TMDB письменно** до публикации в сторах ([источник](https://www.themoviedb.org/talk/5d29d886be4b36756aa16a8a)).
  - Патенты кодеков (H.264/HEVC/E-AC-3/DTS) и логотипы Dolby/DTS — как раньше.
  - Бренды: нельзя «Infuse», «Fedora», ассеты Firecore.

## 6. Twitch в новой схеме

- Облачный шлюз и EventSub-webhook из исследования 06 **убираем**: всё идёт с устройства или сервера пользователя.
- Без логина: каталог/поиск/аватары через Helix требуют app-токен (нужен client secret, который нельзя хранить в открытом приложении) → **вариант:** без логина — избранное хранится локально, данные о стримерах через публичные данные (GQL) или пользователь логинится через Device Code Flow (быстро, по QR на ТВ). **[проверить на прототипе]**
- Запись эфиров 24/7 — на сервере пользователя (режим B) или десктопе.
- Сборки: **full** (GitHub, F-Droid, Flathub, AUR, winget, ISO, Docker) — всё включено; **store** (App Store, Google Play, Microsoft Store) — без загрузок Twitch и без донат-ссылок.

## 7. Репозитории и процесс

- **Решено:** один публичный репозиторий `DenisHumen/project_alpha` (MPL-2.0), сборки — в GitHub Releases этого же репо; принимаем внешние PR (DCO, ревью мейнтейнера, CI для PR из форков — после одобрения). Отдельный `project_alpha-releases` больше не нужен.
- Монорепо: `core/ server/ clients/{apple,android,desktop} distro/ packaging/ tools/ docs/{research,adr,api}` (папка `cloud/` больше не нужна); один Cargo workspace; `justfile`.
- Trunk-based, Conventional Commits, release-please; каналы nightly → beta → stable.
- Для публичного репо: `LICENSE`, `CONTRIBUTING.md` (DCO), `CODE_OF_CONDUCT.md`, `SECURITY.md`, `.github/FUNDING.yml` (донаты прямо в интерфейсе GitHub), шаблоны issue.
- **GitHub Actions для публичных репо бесплатны**, включая macOS-раннеры — минус $40–70/мес из прежней оценки.
- Секреты подписи — в GitHub Secrets; локальные секреты — `.env.local`.

## 8. Публикация

1. **Бесплатно:** GitHub Releases, **F-Droid** (теперь подходит идеально — open source без проприетарных платежей), Flathub, AUR, winget, Microsoft Store, Docker-образ сервера, ISO (Cloudflare R2 + контрольные суммы на GitHub).
2. **Google Play** — $25 разово.
3. **Apple** — $99/год (iOS, tvOS, macOS, нотаризация). Для open source-проектов Apple не даёт бесплатного аккаунта; плата — главный обязательный расход.

Нюансы: подпись Windows (Azure Trusted Signing только США/Канада для физлиц; альтернатива — **SignPath Foundation, бесплатная подпись для open source**) **[проверить условия]**; Homebrew с 01.09.2026 убирает неподписанные casks; Android developer verification в 2027.
