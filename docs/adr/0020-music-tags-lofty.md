# ADR-0020: Читать музыкальные теги в ядре через `lofty`, альбомы собирать по ключу группировки

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** мейнтейнер (решения делегированы владельцем, ADR-0011)
- **Связано:** `MUS-001`, `LIB-001`, `LIB-003`, `MUS-004`, `MUS-008`; [01 §4.11](../research/01-product-ux-design.md), [02 §5](../research/02-client-stack-playback.md), [03 §5](../research/03-metadata-recognition.md); ADR-0005, ADR-0016; [docs/dev/db.md](../dev/db.md) «Музыка»

## Контекст и проблема

Релиз 0.1 читает теги в Dart (`audio_metadata_reader`, `pa_library/music_tags.dart`): только название, артист, альбом, номер и год, без альбомных артистов, дисков, жанров, ReplayGain и обложек, и только на клиенте. Музыкальная библиотека ядра (`pa-library`, `pa-scanner`) должна работать одинаково на клиентах и на медиасервере, по локальным и сетевым источникам (`pa-vfs`), и правильно разбирать сборники и многодисковые альбомы.

## Факторы решения

- Лицензия MIT/Apache (ADR-0005, `cargo deny`), без C-библиотек и GPL (TagLib — LGPL, FFmpeg в ядре сканера не нужен).
- Чтение через `Read + Seek` поверх `pa-vfs`, без локального пути (SMB, NFS).
- Форматы релиза: MP3, FLAC, ALAC/AAC в M4A, Opus, Ogg Vorbis, WAV, DSF.
- Сборники и мультидиск без ручной разметки; повторный скан ничего не перечитывает.

## Рассмотренные варианты

1. `lofty` 0.25 (MIT OR Apache-2.0, чистый Rust): ID3v1/v2, APE, Vorbis Comments, MP4 ilst, RIFF INFO, AIFF; свойства потока; обложки.
2. `symphonia` (MPL-2.0): метаданные вторичны, нет записи и части форматов тегов.
3. FFmpeg (`libavformat`) через `pa-probe`: единый путь с пробингом видео, но тяжёлая нативная зависимость для каждой платформы ради тегов.
4. Набор узких крейтов (`id3`, `metaflac`, `mp4ameta`): разные API, нет Opus/WAV в одном месте.

## Решение

Выбран вариант **1**.

- `pa-scanner::read_tags` читает теги и свойства через `lofty` (`Probe` по содержимому, режим `BestAttempt`), `read_embedded_art` — встроенную обложку. DSF `lofty` не знает: заголовок разбирается вручную, а блок ID3v2 по указателю из заголовка передаётся `lofty` как MP3.
- `pa-scanner::index_music` запускается после `scan`: параллельно читает новые и изменённые аудиофайлы (сравнение с `size`/`mtime`, сохранёнными при чтении), пишет через `pa_library::music`, сообщает `ScanEvent::TagsProgress` / `TagsFailed`. Нечитаемый файл всё равно попадает в библиотеку — по пути (правила 0.1).
- Схема — миграция `MUS-001` (`music_artists`, `music_albums`, `music_album_artists`, `music_tracks`, `music_track_artists`, `music_track_genres`, `music_genres`). Альбом определяется ключом: MusicBrainz release → альбомный артист (или флаг сборника) + название → папка альбома + название; подпапки `CD1`/`Disc 2` относятся к папке альбома. Альбом без альбомного артиста с несколькими основными артистами треков становится сборником «Various Artists».
- ReplayGain хранится в дБ и линейных пиках; `R128_*_GAIN` у Opus переводится к опорному уровню ReplayGain (+5 дБ).
- Обложка — ссылка (источник + путь) на картинку в папке альбома или на трек со встроенной картинкой; байты в базу не копируются.

### Последствия

- Хорошо: один код тегов для клиентов и сервера, сетевые источники без локальных путей, сборники и диски разбираются без MusicBrainz.
- Плохо: определение ALAC/AAC в MP4 — по наличию разрядности (общий API `lofty` не отдаёт кодек); `Release`/`ReleaseGroup` из 03 §5 пока не отдельные сущности — альбом хранит их MBID; одна дорожка = один файл (CUE-листы не поддержаны).
- Требует работы: сопоставление с MusicBrainz и AcoustID (отдельные задачи `MUS-*`), FFI для клиентов (`MUS-004`), перенос библиотеки v0 (`LIB-015`).

### Как проверяем соблюдение

Тесты `pa-scanner/tests/music.rs`: теги всех форматов релиза на сгенерированных в тесте файлах, ReplayGain и R128, многозначные поля, сборники, мультидиск, обложки, нечитаемый файл, повторный скан и перемещение трека между альбомами, коллекция из 5 000 треков. Тесты схемы `pa-library` (FK, индексы, CHECK, документация таблиц).
