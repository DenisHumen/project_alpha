# ADR-NNNN: `pa-probe` — libavformat в рантайме, зеркало префиксов структур, окно чтения «голова + хвост»

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** LIB-006, META-014, PLAY-001, NET-008; [ADR-0005](0005-license-mpl2-dco.md) (LGPL только динамически), [ADR-0027](0027-player-io-adapters-fn-pointers.md) (AVIO-адаптер), [ADR-0033](0033-libsmb2-runtime-loading.md) (тот же приём для libsmb2); `docs/research/03` §4.2 [2], `docs/research/02` §2.3

## Контекст и проблема

Сканеру нужен анализ контейнера: длительность (признак скорера распознавания против тихих ошибок), кодеки, разрешение, HDR и профиль Dolby Vision, звук и Atmos, субтитры, главы, теги, вложения. Анализ идёт по сети (SMB, WebDAV), поэтому читать можно только начало файла (2–8 МБ). FFmpeg у нас — LGPL-сборка `tools/ffmpeg`, только динамически. Rust-ядро должно собираться и тестироваться без FFmpeg на машине. Открытые вопросы: как ядро получает функции и поля структур libavformat, как ограничить чтение и откуда брать то, чего контейнер не объявляет (HDR10+).

## Факторы решения

- LGPL: FFmpeg остаётся заменяемыми `.so`/`.dylib`/`.dll`, никакой линковки при сборке.
- `cargo test --workspace` и CI ядра без FFmpeg; без bindgen и `*-sys`-крейтов.
- Поля `AVFormatContext`, `AVStream`, `AVCodecParameters` нужны напрямую: геттеров у FFmpeg для них нет.
- На Linux приложение может встретить системный FFmpeg 7.x/8.x, а не нашу сборку 9.x.
- Бюджет чтения по сети и предсказуемое время пробы.

## Рассмотренные варианты

1. `ffmpeg-sys-next`/`rsmpeg`: bindgen и FFmpeg на этапе сборки, линковка.
2. C-шим поверх заголовков FFmpeg, собираемый `cc`: те же заголовки при сборке на каждом таргете.
3. Загрузка в рантайме (`libloading`, как ADR-0033) + вручную повторённые `#[repr(C)]`-префиксы публичных структур с проверкой мажорных версий.
4. Указатели на функции от вызывающего кода (как ADR-0027): сканер работает в ядре, а не в плеере, своего экземпляра FFmpeg у него нет.

## Решение

Выбран вариант **3**.

- Крейт `pa-probe`: `Ffmpeg` загружает libavutil, libswresample (если есть), libavcodec и libavformat из `$PA_FFMPEG_LIB_DIR` или через загрузчик платформы (имена по `tools/ffmpeg`: `libavformat.so.63`, `libavformat.63.dylib`, `avformat-63.dll`, на Android `libavformat.so`). Перебираются линейки FFmpeg 9.x, 8.x, 7.x. Нет библиотеки или неподдержанная версия — `ProbeErrorKind::LibraryUnavailable`, а не падение.
- `sys` повторяет только начальные поля структур до последнего читаемого. В пределах мажорной версии FFmpeg добавляет поля только в конец, а нужные префиксы совпадают в libavformat 61 (FFmpeg 7.1) и 63 (FFmpeg 9.0): смещения сняты `offsetof` по обоим наборам заголовков и закреплены тестом. `Ffmpeg` принимает libavformat 61–63 и libavcodec той же мажорной версии; другое — `LibraryUnavailable`.
- ID кодеков между мажорными версиями не стабильны (`AV_CODEC_ID_HEVC` — 173 в 7.1 и 172 в 9.0), поэтому код сравнивает имена из `avcodec_get_name`, а не числа.
- I/O — `AvioContext` из `pa-player-io` (ADR-0027) поверх `WindowedSource`: читаются первые `head_bytes` (8 МиБ) и последние `tail_bytes` (4 МиБ); чтение вне окна возвращает конец файла, libavformat заканчивает анализ на том, что есть. `probesize` = голова. Хвост нужен MP4 с `moov` в конце и последним PTS в MPEG-TS. Результат сообщает `bytes_read`, `window_truncated` и источник длительности (`pts`, `stream`, `bitrate`), чтобы скорер не доверял оценке по битрейту.
- HDR10+, RPU Dolby Vision без `dvcC`, MDCV/CLL в SEI и цветовое описание из sequence header AV1 ищутся чистым Rust в первых 12 видеопакетах HEVC/AV1 (без декодирования). Профиль DV и compatibility id — из `AV_PKT_DATA_DOVI_CONF`. Atmos (E-AC-3 JOC, TrueHD) и DTS:X — по профилю кодека FFmpeg.
- Хук для конвейера: `store::probe_pending` пробует файлы `pa-library` с `probed_at_ms IS NULL` и пишет `container`, `duration_ms`, `video_json`, `audio_langs`, `sub_langs`. `pa-scanner` не меняется: он уже сбрасывает эти колонки при изменении файла.

### Последствия

- Хорошо: ни одной линковки FFmpeg из Rust, ядро собирается и тестируется без него; одна обёртка на все платформы и на системный FFmpeg 7–9.
- Хорошо: проба укладывается в 12 МиБ чтения по сети и не зависит от размера файла.
- Плохо (цена решения): префиксы структур повторены вручную. Защищено проверкой мажорных версий при загрузке, тестом смещений и интеграционным тестом на всём наборе QA-002. Новая мажорная версия FFmpeg требует сверки заголовков и расширения диапазона.
- Плохо: файлы, у которых индекс лежит в середине (MP4 с `moov` больше 4 МиБ в конце), не открываются: `InvalidData`. Окно настраивается.
- Нейтрально: libavformat пишет предупреждения в stderr (уровень логов процесса не меняем: его делит плеер).

### Как проверяем соблюдение

`cargo tree -p pa-probe` без FFmpeg-крейтов; `nm` наших бинарников без определённых `av*`; тест `sys::offsets_match_ffmpeg_headers`; `tests/media.rs` против `tools/ffmpeg/out/linux-x86_64/lib` и `just tests::media` (на машине без FFmpeg пропускается).
