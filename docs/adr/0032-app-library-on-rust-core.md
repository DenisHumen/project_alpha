# ADR-0032: Медиатека приложения на Rust-ядре через крейт `pa-catalog` и адаптер `RustLibrary`

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** мейнтейнер (решения делегированы владельцем, ADR-0011)
- **Связано:** `UI-024`, `LIB-015`, `LIB-004`, `META-013`, `CORE-002`; [ADR-0015](0015-frb-native-assets-committed-bindings.md), [ADR-0016](0016-library-sqlite-schema-refinery.md), [ADR-0025](0025-library-search-fts5.md); [docs/dev/db.md](../dev/db.md) §«Переход с pa_library v0»

## Контекст и проблема

Релиз 0.1 работает на Dart-пакете `pa_library` v0: свой сканер, парсер v0, своя упрощённая база. В ядре уже есть схема v1 (`pa-library`), сканер (`pa-scanner`, теги музыки), парсер и индекс названий (`pa-recognition`), поиск FTS5 и прогресс с Up Next — но нет слоя, который собирает их в «медиатеку приложения»: создаёт произведения и эпизоды из распознанных файлов без провайдеров, отдаёт экраны «Фильмы/Сериалы/Музыка» и переносит базу v0. Экраны приложения менять не хотим: они работают с интерфейсом `Library`.

## Факторы решения

- Экраны и тесты приложения не меняются (интерфейс `Library` из контракта релиза 0.1).
- Логика — в ядре, одна для Flutter (FRB) и будущих нативных клиентов (UniFFI); FRB-фасад остаётся тонким.
- Переход обратим, пока Rust-ядро не стало умолчанием.
- Прогресс хранится под стабильным ключом `MediaKey` (синхронизация, LIB-011), а у файлов без TMDB это `file:<fingerprint>`.

## Рассмотренные варианты

1. Новый крейт `pa-catalog` (конвейер скана, локальное распознавание, представления, импорт v0) + тонкий `api/library.rs` в `pa-frb` + адаптер `RustLibrary implements Library` в `pa_library`.
2. Всё в `pa-frb` (логика в фасаде).
3. Сразу заменить реализацию в `pa_library` без флага.

## Решение

Выбран вариант **1**.

- `core/crates/pa-catalog` — `Catalog` над одной базой v1: источники; скан = `pa_scanner::scan` → `index_music` → отпечатки → локальное распознавание → удаление сирот → `search::sync`; представления «фильм/сериал/эпизод/трек» с id `m<work>`, `s<work>`, `e<episode>`, `t<track>`; прогресс через `pa_library::progress` (профиль 1); исправление матча; импорт v0 (часть `LIB-015`, нужная приложению). Скан идёт на своём соединении, запросы — на основном (WAL), сканы сериализуются.
- Локальное распознавание: лучшая гипотеза парсера; эпизод → произведение `show` (или `anime` по признаку аниме) по loose-ключу `TitleKey`, фильм → `movie` по ключу и году; матч `auto`/`rule` с весом гипотезы. Ручное исправление ставит `user_set`, старое название остаётся синонимом в `titles`. Сопоставление с TMDB (`META-013`) добавит `external_ids` к тем же произведениям.
- Отпечаток файла для ключа `file:` — **OSHash** (размер + 64-битные слова LE первых и последних 64 КиБ, 16 hex), пишется в `files.fingerprint` и `files.oshash`. `LIB-004` обязан сохранить это значение, иначе прогресс под `file:`-ключами потеряет файлы.
- `pa_library` получает `RustLibrary` (зависимость `pa_core`); приложение включает его флагом `--dart-define=KINOLUNE_RUST_CORE=true`. Пока флаг не умолчание, база v0 импортируется при каждом запуске (идемпотентно) и **не** переименовывается — можно вернуться на v0. При переключении умолчания — переименование в `*.v0.bak` по db.md.

  **Дополнение (UI-024 ч. 2, 2026-11-14):** Rust-ядро — умолчание. Приложение открывает медиатеку через `openAppLibrary` (`pa_library`): `kinolune-core.db`; база v0 `kinolune.db` импортируется при первом запуске и переименовывается в свободное `kinolune.db.v0.bak[.N]` (ничего не удаляется), после импорта приложение запускает скан (теги музыки, элементы SMB). Dart-реализация v0 остаётся источником импорта и запасным путём: `--dart-define=KINOLUNE_RUST_CORE=false`, отсутствие нативной библиотеки или ошибка открытия/импорта ядра — тогда открывается v0 (из свежей копии `.v0.bak`, если файл уже переименован). Язык метаданных следует языку интерфейса (`ru` → `ru-RU`, иначе `en-US`); смена языка не сбрасывает состояние — ядро само перезапрашивает работы с метаданными на другом языке при следующем скане.

Не входит: постеры из кэша изображений (`LIB-013`; пока локальные картинки рядом с файлами, как в v0), SMB через `pa-vfs` (пока шара монтируется через gio, как в v0, и сканируется как локальная папка).

### Последствия

- Плюсы: одна логика медиатеки для всех клиентов; поиск FTS5, Up Next и музыкальные таблицы в приложении; экраны не тронуты.
- Минусы: каждая сборка приложения собирает Rust (Native Assets) — дольше CI; без TMDB в Rust-режиме меньше постеров и описаний, чем в v0 с ключом.
- Риск: OSHash коротких файлов (< 128 КиБ) отличается от «канонических» реализаций, которые такие файлы не хэшируют; для медиа это не встречается.
