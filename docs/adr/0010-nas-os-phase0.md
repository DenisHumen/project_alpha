# ADR-0010. NAS-ОС, фаза 0: образ на bootc, Go для системных компонентов, медиасервер нативно в образе

- Статус: **принят** (прототип DIST-001)
- Дата: 2026-11-13
- Задача: DIST-001 · исследование: [05](../research/05-nas-linux-distro.md) §1.4, §2.3, §4, §5.2, §8 (фаза 0)

> Номер 0010 выбран, чтобы не пересекаться с зарезервированными в ROADMAP ADR 0001–0009 (DOC-001, PLAY). Если DOC-001 введёт другой шаблон, ADR переоформляется без смены решения.

## Контекст

Нужна NAS-ОС «для людей»: атомарные обновления с откатом, свежее ядро и Mesa для аппаратного транскодирования, Secure Boot без собственного shim, сборка в GitHub Actions без нашей инфраструктуры. Исследование 05 рекомендует image-based ОС на bootc. Фаза 0 должна была подтвердить это на практике и закрыть три вопроса: база и механизм обновлений, язык установщика и системных демонов, способ поставки медиасервера (нативно в образе или Podman Quadlet).

Прототип — `distro/Containerfile` и сценарий `distro/tests/vm-switch-rollback.sh`. Результаты проверки — в `distro/README.md`.

## Решение

1. **База — `quay.io/fedora/fedora-bootc:45`, пин по digest манифест-листа.** Обновление base — отдельный PR со сменой digest и прогоном VM-сценария. План Б без изменений: CentOS Stream 10 bootc (канал `lts`). Название ОС не содержит «Fedora» (DIST-003, DEC-004).
2. **Обновления — штатные `bootc switch | upgrade | rollback`.** Таймер `bootc-fetch-apply-updates.timer` в образе замаскирован: обновлениями управляет наш `alpha-updated` (DIST-009). Канал = тег в реестре; переход на конкретный digest и обратно на тег проверен в прототипе (нужно для поэтапной раскатки, DIST-012).
3. **Установщик и системные демоны (`alpha-installer`, `alpha-admin`, `alpha-updated`, storage-сервис) — на Go.** Причины: один статический бинарник без рантайма в образе; зрелые библиотеки для D-Bus (`godbus`), systemd, NetworkManager, UDisks2; bubbletea/teatest для TUI установщика; сам bootc-стек и containers/image написаны на Go/Rust, примеры и инструменты — под рукой; низкий порог для внешних контрибьюторов. Rust остаётся языком медиасервера и ядра; общий код между ними не нужен — граница проходит по HTTP/unix-сокету.
4. **Медиасервер — нативно в образе** (`/usr/lib/alpha-media`, systemd-юнит, состояние в `/var/lib/alpha-media`). ОС и медиасервер выпускаются и тестируются вместе, откат ОС откатывает и сервер, проще доступ к GPU (`/dev/dri`, NVIDIA). Хотфикс сервера = новый образ; после rechunk (DIST-002) это небольшая дельта. **Podman Quadlet** с logically bound images оставляем для опциональных приложений (фаза 3) и как запасной вариант, если сервер начнёт выходить чаще ОС.
5. **Состав образа фазы 0:** Samba (SMB3, `vfs_fruit`), wsdd, Avahi + nss-mdns, firewalld (зона `home`: samba, mdns, ws-discovery, http/https, порт медиасервера), smartmontools, mdadm, btrfs-progs, greenboot, Cockpit (установлен, `cockpit.socket` выключен). Наши сервисы пока — заглушки с `/health`.
6. **Состояние** создаётся через `tmpfiles.d` (bootc не переносит `/var` из образа); конфиги в `/etc` — по 3-way merge bootc.

## Последствия

- `+` Атомарные обновления и откат подтверждены на VM; доставка ОС = обычный OCI-образ в GHCR, сборка — `podman build` (или `docker build`) в CI.
- `+` Secure Boot «из коробки» на загрузочной цепочке базы.
- `−` Любой хотфикс медиасервера требует пересборки и перезагрузки ОС; смягчается rechunk и soft-reboot.
- `−` Major-апгрейд базы (45 → 46) — наш выпуск; закладываем 1–2 месяца на каждую версию.
- `−` Для записи диска нужен привилегированный контейнер (loop-устройства, mkfs): в CI — runner с rootful podman/docker; локально — пользователь в группе `docker`. Rootless podman не подходит.
- Открыто (вне DIST-001): юридическая позиция по кодекам (DEC-005), проверка на железе Intel N100/AMD APU (`vainfo`, QSV/VAAPI), live-ISO (DIST-007), подписи и `policy.json` (DIST-002).
