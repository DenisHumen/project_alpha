# ADR-NNNN: Диски в медиатеке — основной поток по размеру, образы ISO не воспроизводятся

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** LIB-017, LIB-007, LIB-010, META-013, LIB-018; [ADR-0032](0032-app-library-on-rust-core.md), [ADR-0038](0038-network-playback-loopback-proxy.md)

## Контекст и проблема

LIB-007 научил анализ папок (`pa_scanner::structure`) видеть диски: папку с `BDMV/` или `VIDEO_TS/` и файл `.iso` он делает одной группой `disc`. Но скан (`pa_scanner::scan`) пропускал папки `BDMV`/`VIDEO_TS` и не знал расширений `.vob` и `.iso`, поэтому в `files` не было ни одного файла диска, и до распознавания и приложения диски не доходили.

Нужно решить: какие файлы диска записывать, какой поток играть и что делать с образом `.iso`, если наш плеер (LGPL-сборки libmpv и FFmpeg) его не играет.

## Факторы решения

- Без новых зависимостей и без GPL: в клиентах только LGPL FFmpeg/mpv (`docs/research/02` §2.2, `tools/mpv/README.md`), `dvdnav` в mpv запрещён (`tools/mpv/lib/mpv.sh`), libbluray в сборках нет (`auto_features=disabled`, FFmpeg `--disable-autodetect`).
- Воспроизведение — существующим путём: локальный файл напрямую, сетевой — через loopback-прокси (ADR-0038); плееру уходит один URI.
- Выбор основного потока стабилен между сканами: от него зависят совпадение (`matches`), версия (LIB-010) и прогресс.
- Просто и дёшево по сети: без чтения содержимого файлов диска на этапе анализа.

## Рассмотренные варианты

Основной поток Blu-ray:

1. **Самый большой `BDMV/STREAM/*.m2ts`** (при равенстве — самый длинный по `pa-probe`).
2. Самый длинный `.m2ts` по длительности `pa-probe`.
3. Самый длинный плейлист `BDMV/PLAYLIST/*.mpls` (разбор MPLS, склейка клипов).

Образ `.iso`:

1. **Показывать фильм, но помечать неиграбельным** (`pa_catalog::Unplayable::DiscImage`).
2. Отдавать mpv как есть.
3. Читать UDF/ISO 9660 своим кодом и отдавать плееру поток из образа.

## Решение

Скан записывает потоки дисков: заходит в `BDMV/` (внутри — только в `STREAM/`) и в `VIDEO_TS/`, расширения `.vob` и `.iso` считаются видео (`ScanRules::disc_streams`, по умолчанию включено). `CERTIFICATE/`, `AUDIO_TS/`, `BDMV/PLAYLIST`, `BDMV/BACKUP` и прочее не листаются.

Основной поток — вариант **1** для Blu-ray: самый большой `.m2ts`. Длительность есть только после `pa-probe`, а анализ папок идёт до него; выбор по размеру не меняется, когда длительности появляются. Для DVD — набор `VTS_NN_*.VOB` (кроме `_0`, меню) с наибольшим суммарным размером; его VOB — части по порядку. Остальные потоки диска — `Role::Ignore` (в `group_assets`): у них нет совпадения, они не попадают в элементы и в поиск.

Образ — вариант **1**. Без libbluray и libdvdnav у mpv нет навигации по дискам; FFmpeg видит образ как сырые байты. DVD-образ в лучшем случае читается как один поток MPEG-PS с меню, без титулов и надёжной перемотки; Blu-ray-образ не открывается. Фильм из образа есть в медиатеке с метаданными, а `Item::unplayable` / `Version::unplayable()` говорят клиенту не открывать плеер и показать причину.

Не входит: разбор MPLS, склейка VOB-набора и частей `cd1`/`cd2` в одно воспроизведение, вывод причины в приложении — задача LIB-020.

### Последствия

- Хорошо: Blu-ray и DVD в папках играют основной фильм тем же путём, что и обычные файлы, локально и по сети; образ виден в медиатеке с постером и описанием.
- Плохо: диски с seamless branching (фильм из многих клипов по плейлисту) играют только самый большой клип. DVD играет только первый VOB набора (около 1 ГБ), пока нет склейки (LIB-020). ISO не играет.
- Нейтрально: `pa-probe` и OSHash считаются для всех потоков диска (по 64 КиБ с концов и заголовок контейнера на файл); на дисках с сотнями клипов первый скан по сети дольше.
