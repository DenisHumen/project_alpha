# ADR-NNNN: SMB через libsmb2 — загрузка в рантайме, пул контекстов, read-ahead с параллельным prefetch

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** NET-002, NET-003, NET-011, CI-004, CI-012; [ADR-0005](0005-license-mpl2-dco.md) (LGPL только динамически), [ADR-0013](0013-pa-vfs-blocking-positional-reads.md) (синхронный `pa-vfs`), [ADR-0027](0027-player-io-adapters-fn-pointers.md) (FFmpeg и libmpv без линковки из Rust); `docs/research/02` §3.1, §4

## Контекст и проблема

SMB — главный источник медиа на NAS, а в Android-клиенте его нет совсем. Research 02 §4 выбрал [libsmb2](https://github.com/sahlberg/libsmb2) (C, LGPL-2.1+, SMB 2.0.2–3.1.1, встроенный NTLMSSP, подпись и шифрование SMB3, работает на iOS и tvOS). LGPL-код у нас — только отдельной заменяемой библиотекой (§0.3 п.10). Нужно решить: как Rust-ядро получает функции libsmb2, как из небезопасного по потокам контекста сделать `Vfs` для многих потоков и как держать поток 4K-ремукса по Wi-Fi.

## Факторы решения

- LGPL: libsmb2 — отдельный `.so`, `.dll`, `.dylib` или embedded framework, пользователь может её заменить.
- `cargo test --workspace` и CI ядра должны работать без собранной libsmb2 (так же, как для FFmpeg и libmpv в ADR-0027).
- Один код загрузки для Linux, Windows, Android, macOS, iOS и tvOS; на iOS динамический код — только во framework внутри бандла.
- Контекст libsmb2 не потокобезопасен; сканер и плеер читают из разных потоков (`Arc<dyn Vfs>`, `read_at(&self)`).
- Поток 80 Мбит/с при RTT 30 мс и 1 % потерь (NET-003): один запрос за раз на одном TCP-соединении этого не даёт.

## Рассмотренные варианты

1. `smb2-sys` с `cargo:rustc-link-lib=dylib=smb2` в `build.rs`: линковка на этапе сборки.
2. Загрузка библиотеки в рантайме через `libloading` (ISC) и таблица указателей на функции.
3. Pure-Rust клиент `smb` (smb-rs, MIT) вместо libsmb2.

## Решение

Выбран вариант **2**.

- `tools/libsmb2` собирает libsmb2 6.3.x только как разделяемую библиотеку (на iOS и tvOS — `smb2.framework`, плюс `smb2.xcframework`) с лицензионным гейтом по образцу `tools/ffmpeg` и `tools/mpv`. Kerberos выключен: NTLMSSP встроенный, внешних зависимостей нет.
- Крейт `pa-smb2`: `sys` — C ABI (типы и таблица функций), `Smb2Lib` — загрузка (`$PA_SMB2_LIB`, затем имена платформы, в том числе `@rpath/smb2.framework/smb2`), `Context` — безопасная обёртка (`Send`, не `Sync`, все вызовы через `&mut self`; файлы — `FileId` с проверкой владельца вместо сырых указателей). Ошибки классифицируются по NT status, затем по errno (значения errno различаются между ОС).
- Отсутствие библиотеки — ошибка `LibraryUnavailable` при первом SMB-подключении, а не падение приложения.
- Проверка «линкуется динамически» из NET-002: гейт `tools/libsmb2/check-license.sh` на каждом таргете (тип файла, зависимости через `readelf`/`otool`/`objdump`, install name `@rpath`), а для нативных таргетов — `ldd`/`otool -L` тестовой C-программы. Наши Rust-бинарники libsmb2 не линкуют вовсе.
- Крейт `pa-vfs-smb` (NET-003): `SmbFs` держит пул контекстов (по умолчанию до 6), каждый со своим кэшем открытых файлов. `list` и `stat` — один запрос на свободном контексте. `ByteSource` читает случайные запросы напрямую, а при последовательном чтении включает read-ahead: блоки по 1 МБ, буфер 64 МБ по умолчанию (настраивается, ориентир 32–256 МБ), до 4 блоков параллельно на разных соединениях в фоновых потоках. Обрыв соединения выбрасывает контекст из пула, запрос повторяется один раз на новом.
- SMB1 libsmb2 не умеет. Флаг `allow_smb1` в конфигурации есть по требованию NET-003, но включённый он даёт `Unsupported` с подсказкой включить SMB2 на сервере: старый протокол не поддерживаем даже по флагу.

### Последствия

- Хорошо: LGPL-библиотека остаётся заменяемым файлом, ядро собирается и тестируется без неё; одна обёртка на все платформы.
- Хорошо: параллельные запросы на нескольких соединениях обходят ограничение одного TCP-потока при потерях.
- Плохо (цена решения): сигнатуры и `struct smb2_stat_64` повторены вручную в `pa-smb2::sys`. Защищено закреплённой версией (6.x держит ABI и soname), проверкой экспортов в гейте и тестами против реальной библиотеки.
- Плохо: `smb2_get_nterror` нет в `libsmb2.syms`, поэтому MSVC-сборка его не экспортирует; наша Windows-сборка — mingw-w64, экспортирует всё. Для mingw нужен патч (`patches/libsmb2/0001`), он описан и войдёт в архив исходников.
- Нейтрально: каждый открытый `SmbFs` держит до 6 TCP-соединений и потоки prefetch; при закрытии источника они освобождаются.

### Как проверяем соблюдение

`cargo tree -p pa-smb2` — только `libloading`; `nm` наших бинарников не содержит определённых `smb2_*`; CI `libsmb2.yml` гоняет гейт на всех таргетах; `pa-vfs-smb` проходит контракт-сьют `pa-vfs` против Samba в Docker (`tests/servers/run.sh`).
