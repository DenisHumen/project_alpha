# ADR-NNNN: Сетевые источники — скан через `pa-vfs`, воспроизведение через loopback-прокси `pa-proxy`

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** LIB-018, NET-007, NET-008, NET-011, LIB-005, LIB-006, UI-005; [ADR-0013](0013-vfs-blocking-api.md), [ADR-0031](0031-webdav-backend-blocking-reqwest.md), [ADR-0032](0032-app-library-on-rust-core.md), [ADR-0033](0033-libsmb2-runtime-loading.md)

## Контекст и проблема

До LIB-018 приложение сканировало SMB-шару, монтируя её через `gio mount` (только Linux, GVfs, пароль подавался на stdin), а пароль хранило второй копией во `flutter_secure_storage`: ядро пароль наружу не отдаёт. WebDAV не индексировался вовсе, Android SMB не умел. При этом в ядре уже есть бэкенды `pa-vfs` для SMB (libsmb2, NET-003) и WebDAV (NET-004), менеджер источников с паролями в `pa-secrets` (NET-011) и адаптеры `ByteSource` для FFmpeg AVIO и mpv `stream_cb` (NET-008).

Нужно решить две вещи: как скан (`pa-catalog`) получает файловую систему источника и как плеер приложения (media_kit поверх libmpv) читает сетевой файл.

## Факторы решения

- Без монтирования и без внешних утилит; одинаково на Linux и Android (и дальше на Apple).
- Пароль хранится в одном месте — в `pa-secrets`; Dart его не видит.
- media_kit принимает только URI; доступа к `mpv_handle` у приложения нет.
- Перемотка без перекачки файла: чтение по смещению (`Range`).
- Безопасность: другие приложения и веб-страницы на устройстве не должны читать шары пользователя.
- Малый объём кода и без новых зависимостей с неподходящей лицензией.

## Рассмотренные варианты

Скан:

1. **Трейт `Connector` в `pa-catalog`**, реализация `SourcesConnector` поверх `SourceManager::connect`.
2. Каталог сам открывает хранилище секретов и строит бэкенды.
3. Оставить монтирование для SMB, WebDAV — через ядро.

Воспроизведение:

1. **Loopback HTTP Range-прокси `pa-proxy` (NET-007)**: `http://127.0.0.1:<порт>/<токен>/<id источника>/<путь>`.
2. mpv `stream_cb` через `pa-player-io` (NET-008): свой протокол `pa://` в libmpv.
3. Копировать файл во временный каталог перед воспроизведением.

## Решение

Скан — вариант **1**: `Catalog` хранит `Arc<dyn Connector>`; по умолчанию `LocalConnector` (только `file://`), приложение через `CoreLibrary.connect_sources(data_dir)` ставит `SourcesConnector`, который открывает тот же экземпляр хранилища секретов, что и `CoreSources` (общий на процесс, `pa-frb/src/shared.rs`). Скан, инкрементальный пересказ наблюдателя (LIB-005, сетевые источники — по таймеру), анализ структуры, теги, отпечатки и зонд `pa-probe` (LIB-006) читают через один `Vfs`.

Воспроизведение — вариант **1**: крейт `pa-proxy` (только std и `uuid`): `GET`/`HEAD`, один диапазон `bytes=`, keep-alive, лимит соединений (16, сверх — `503`), таймаут простоя; путь без токена — `403`. Токен — 122 случайных бита на процесс, не логируется. `SourceOpener` в `pa-catalog` разбирает `<id>/<путь>`, кэширует `Vfs` источника и четыре последних открытых файла, при ошибке переподключается. Dart получает базовый URL (`CoreLibrary.stream_base_url`) и кладёт URL файла в `LibraryItem.streamUri`; на экране по-прежнему показывается `filePath` (адрес источника и путь).

`stream_cb` (вариант 2) отклонён для приложения: media_kit не даёт зарегистрировать протокол в своём `mpv_handle`, понадобился бы форк плагина и нативный код на каждой платформе. Прокси работает с любым плеером, которому можно дать URL (media_kit, ExoPlayer, AVPlayer), и проверяется `curl`/`ffprobe`. Адаптеры NET-008 остаются для нативных плееров, где у нас есть свой `mpv_handle` (PLAY-DSK, PLAY-APL).

Монтирование через `gio` удалено. Старая копия пароля SMB из `flutter_secure_storage` один раз переносится в `pa-secrets` (если там пароля нет) и удаляется; без менеджера источников ядра (v0-фолбэк) она не трогается, а v0-библиотека читает только шару, уже смонтированную пользователем.

### Последствия

- Хорошо: SMB и WebDAV сканируются и играют одинаково на всех платформах ядра; пароль в одном месте; нет зависимости от GVfs.
- Хорошо: прокси — отдельный небольшой крейт, переиспользуется для нативных плееров (NET-007).
- Плохо: лишний локальный HTTP-переход (копирование через сокет); на скорость сети не влияет.
- Плохо: любой процесс устройства может стучаться в порт; защищает только токен в URL — URL нельзя логировать и показывать.
- Плохо: локальные постеры рядом с файлами сетевых источников приложение пока не показывает (оно ищет их через `dart:io`); постеры провайдеров работают.
- Нейтрально: SMB в собранном приложении требует libsmb2 рядом с ним (ADR-0033); упаковка libsmb2 в AppImage и APK — отдельная задача.
