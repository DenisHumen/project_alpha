# ADR-NNNN: Xcode-проект tvOS-приложения генерируется XcodeGen из `project.yml`

- **Статус:** Предложен
- **Дата:** 2026-11-14
- **Решают:** владелец проекта (мейнтейнер); участники обсуждения — по PR
- **Связано:** `TV-001`, `CORE-003`, `CI-007`, ADR-0002, ADR-0007

## Контекст и проблема

tvOS-приложение (`clients/apple/TVApp`, ADR-0002) — это Xcode-проект: приложение, unit- и UI-тесты, зависимость от локального SwiftPM-пакета `PACore`. Файл `project.pbxproj` — машинный формат с UUID: его плохо ревьюить, он часто конфликтует при параллельной работе, а агенты и контрибьюторы без Mac не могут его ни сгенерировать, ни проверить. Собираем мы только в GitHub Actions (`macos-15`), локального Mac нет.

## Факторы решения

- Проект можно писать и ревьюить без Mac, обычным текстом.
- Нет конфликтов в `pbxproj` при параллельных PR.
- Одинаковая сборка в CI и у разработчика с Xcode.
- Минимум внешних зависимостей и их воспроизводимость.

## Рассмотренные варианты

1. XcodeGen: `project.yml` в репозитории, `TVApp.xcodeproj` генерируется и не коммитится.
2. Закоммиченный `TVApp.xcodeproj`, написанный вручную или в Xcode.
3. Tuist (манифест на Swift).
4. Только SwiftPM, без Xcode-проекта.

## Решение

Выбран вариант **1 (XcodeGen)**: короткий читаемый YAML, генерация за секунды, проект не хранится в git.

- Источник истины — `clients/apple/TVApp/project.yml`; `TVApp.xcodeproj/` в `.gitignore`.
- Генерация: `just apple tv-project` (или `cd clients/apple/TVApp && xcodegen generate`).
- В CI (job `tvapp` в `.github/workflows/apple-core.yml`) XcodeGen ставится из GitHub Releases конкретной версии с проверкой SHA-256.
- Флейвор (ADR-0007) задаётся в `project.yml` через `SWIFT_ACTIVE_COMPILATION_CONDITIONS`: tvOS распространяется только через App Store, поэтому все конфигурации — `store` (`PA_FLAVOR_STORE`).

### Последствия

- Хорошо: изменения проекта видны в diff; нет конфликтов `pbxproj`; проект можно править без Mac.
- Плохо: нужен ещё один инструмент (XcodeGen) у разработчика на Mac; настройки, сделанные в Xcode руками, теряются при перегенерации — их переносят в `project.yml`.
- Требует работы: CI-007 может свести Apple-джобы в один; при появлении iOS/macOS-приложений на SwiftUI — тот же подход.

## Плюсы и минусы вариантов (опц.)

### Закоммиченный `.xcodeproj`

- Плюс: не нужен генератор, привычно для Xcode.
- Минус: `pbxproj` невозможно корректно написать и проверить без Mac; конфликты при параллельной работе.

### Tuist

- Плюс: манифест на Swift, кэш сборки.
- Минус: тяжелее (свой рантайм и версии), избыточен для одного приложения.

### Только SwiftPM

- Плюс: без генератора.
- Минус: SwiftPM не собирает tvOS-приложение с UI-тестами и Info.plist; для App Store всё равно нужен Xcode-проект.
