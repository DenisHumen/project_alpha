# ADR-0001: Общее ядро на Rust с привязками UniFFI и flutter_rust_bridge

- **Статус:** Принят
- **Дата:** 2026-11-13
- **Решают:** владелец проекта
- **Связано:** `CORE-001`…`CORE-010`, `docs/STRATEGY.md` §3, `docs/research/04` §1.2–1.3, `docs/research/02` §1.4

## Контекст и проблема

Продукт работает на семи платформах: Android, Android TV, iOS/iPadOS, tvOS, macOS, Windows, Linux. Плюс медиасервер пользователя (режим B), который должен жить на слабом NAS (ARM, 1–2 ГБ RAM). Бизнес-логика — сетевые источники (SMB/NFS/WebDAV), медиатека на SQLite, распознавание, метаданные, синхронизация, клиенты Plex/Jellyfin/Emby, Twitch Helix — одинакова везде. Если писать её в каждом UI-стеке отдельно, получится 3–4 расходящиеся реализации. Нужен один общий слой и способ вызывать его из Dart (Flutter), Swift (SwiftUI, AVFoundation) и Kotlin (Media3).

## Факторы решения

- Одинаково хорошее встраивание во все клиентские платформы, включая tvOS.
- Тот же код работает в сервере на NAS: мало памяти, без GC-пауз.
- Нейтральность к UI-фреймворку (не тянет за собой Compose или JVM).
- Привязки к FFmpeg, libsmb2, libnfs без мучений с кросс-компиляцией.
- Большую часть кода пишут AI-агенты: строгий компилятор ловит их ошибки до ревью.
- Лицензии зависимостей совместимы с MPL-2.0 и App Store (ADR-0005).

## Рассмотренные варианты

1. **Rust-ядро** + UniFFI (Swift/Kotlin) + flutter_rust_bridge (Dart).
2. **Go-ядро** через gomobile / cgo.
3. **Kotlin Multiplatform-ядро** (Kotlin/Native на Apple, JVM на десктопе).
4. **C++-ядро** с ручным C API, JNI и `ffigen`.
5. Без общего ядра: логика в Dart (Flutter) + отдельно Swift для tvOS.

## Решение

Выбран вариант **1 — Rust**. Это единственный кандидат, который одинаково хорошо встраивается во все шесть клиентских ОС и одновременно даёт лёгкий сервер для NAS.

Конкретика:

- Ядро — набор крейтов `core/crates/pa-*` в одном Cargo workspace с `server/` и `tools/*` (раскладка — ADR-0006).
- **Swift и Kotlin** получают API через **UniFFI** (proc-macro), фасадный крейт `pa-ffi`. Каждый домен экспортируется своим модулем `pa-ffi/src/<domain>.rs`.
- **Dart/Flutter** получает API через **flutter_rust_bridge** в пакете `clients/flutter/packages/pa_core`.
- Сгенерированные привязки не коммитятся, их генерирует `just bindings`. Исключение — файлы, которые Xcode требует на диске; их актуальность проверяет CI.
- Воспроизведение видео **не входит** в ядро. Ядро отдаёт плееру источник байтов (`ByteSource`: адаптеры для `AVIOContext`, mpv stream callbacks, Media3 `DataSource` и loopback HTTP Range-прокси) и политику выбора дорожек. Сам плеер — нативный (ADR-0003).
- Сеть: SMB — `libsmb2`, NFS — `libnfs` (обе LGPL-2.1, только динамическая линковка; ADR-0005), WebDAV — `reqwest` + свой PROPFIND.
- Асинхронность — `tokio`; БД — SQLite (WAL) с FTS5.

### Последствия

- Хорошо: одна реализация логики для всех клиентов и сервера; FFI-граница заставляет держать API ядра узким и стабильным; strict-компилятор работает как «бесплатный ревьюер».
- Плохо: высокий порог входа для контрибьюторов; долгая компиляция (нужен `sccache` в CI); tvOS — tier-3 target Rust, нужен nightly или `build-std` и отдельная проверка в CI; две системы привязок (UniFFI и FRB) нужно держать согласованными.
- Требует работы: `CORE-001` (каркас UniFFI), `CORE-002` (FRB-пакет), `CORE-010` (`core_version()` со всех платформ — критерий выхода M0).

### Как проверяем соблюдение

- CI собирает ядро под все таргеты и генерирует привязки на каждом PR.
- `cargo deny` проверяет лицензии зависимостей.
- Новая бизнес-логика в Dart/Swift/Kotlin, которая дублирует ядро, отклоняется на ревью.

## Плюсы и минусы вариантов

### Go

- Плюс: проще язык, зрелый `go-smb2`, отличный сервер.
- Минус: gomobile тяжёлый (+10–20 МБ рантайма, GC), плохо поддерживается и проблемен на tvOS; GC и сигналы мешают встраиванию в чужой процесс.

### Kotlin Multiplatform

- Плюс: нативен для Android и Media3.
- Минус: десктоп только через JVM или Kotlin/Native; тяжелее по памяти на NAS; нет нормального SMB на всех платформах; тянет в Compose.

### C++

- Плюс: нативно для FFmpeg.
- Минус: ручные привязки к трём языкам, ниже безопасность памяти, сложнее для агентов.

### Без общего ядра

- Плюс: меньше FFI.
- Минус: tvOS на SwiftUI (ADR-0002) и сервер всё равно потребуют второй реализации; расхождение поведения распознавания и синхронизации.
