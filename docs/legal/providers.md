# Условия провайдеров метаданных и сервисов (LEGAL-002)

> **Это не юридическая консультация.** Документ — инженерная сводка публичных условий сервисов, составленная участниками проекта (с помощью AI-агента) по официальным страницам на **2026-11-13**. Условия меняются; перед публикацией сборок и перед обращением к провайдеру сверяйтесь с первоисточником. Спорные вопросы решает владелец проекта, при необходимости — с юристом.

Контекст проекта (см. [STRATEGY.md](../STRATEGY.md) v2): open source (MPL-2.0), некоммерческий, финансируется добровольными пожертвованиями (GitHub Sponsors, Open Collective, Liberapay, Ko-fi, Boosty), **нет серверов проекта** — все запросы идут напрямую с устройства или сервера пользователя. Сборки распространяются через GitHub, F-Droid, Flathub и т. п., а также бесплатно через App Store и Google Play.

Обозначения:

- **✅** — подтверждено официальной страницей провайдера (ссылка в столбце «Источник»).
- **[не подтверждено]** — официальная страница не загрузилась или вопрос в ней не освещён; сведения из вторичных источников или выводы.
- «Ключ проекта» — ключ/client ID, зарегистрированный на project_alpha и поставляемый в сборках. «Ключ пользователя» (BYOK) — пользователь вводит свой.

**Общее правило для ключей проекта:** в git ключи не коммитятся (CLAUDE.md). Ключи проекта подставляются при сборке из GitHub Secrets; при этом из бинаря их всё равно можно извлечь, поэтому у каждого провайдера должен быть «свой ключ» как fallback на случай отзыва. Для F-Droid (сборка из исходников) нужен отдельный механизм (`.env`-шаблон или ввод ключа при первом запуске) — решить в META-009.

### 2.2. Аниме

#### AniDB (HTTP API и UDP API)

> Официальная wiki (wiki.anidb.net) при проверке закрыта Cloudflare bot-check (403). Обходить защиту не стали. Ниже — по выдержкам из официальной wiki в поисковой выдаче и сообществу; **весь раздел требует ручной сверки владельцем** при регистрации клиента.

1. Клиент обязан быть **зарегистрирован** на AniDB; в запросах — `client=` и `clientver=` (целое). Частично подтверждено.
2. [не подтверждено] Коммерческое использование — по отдельному согласованию с AniDB.
3. [не подтверждено] Правило об одном зарегистрированном имени клиента для open source-проекта не найдено; практика сообщества — одно имя клиента на проект. UDP требует логина **аккаунта пользователя** (AUTH).
4. [не подтверждено] Требования атрибуции не найдены; указать AniDB в «О программе».
5. [не подтверждено] HTTP: не чаще ~1 запроса в 2 с. UDP: ~1 пакета в 2 с длительно (короткие всплески допустимы); в ROADMAP (META-011) заложен более строгий лимит 1 пакет в 4 с — оставить его. При превышении — бан по IP/аккаунту на дни.
6. Частично подтверждено: ожидается **агрессивное локальное кэширование**; повторный запрос тех же данных в течение суток может привести к бану; API нельзя использовать для «выкачивания» AniDB. Дамп названий `anime-titles.xml.gz` — не чаще раза в сутки [не подтверждено].
7. [не подтверждено] Редистрибуция дампа названий в бандле — не делать без разрешения AniDB (см. [anime-mappings.md](anime-mappings.md) про `animetitles.xml`).
8. https://wiki.anidb.net/HTTP_API_Definition, https://wiki.anidb.net/UDP_API_Definition (страницы регистрации клиента — на anidb.net в профиле)
