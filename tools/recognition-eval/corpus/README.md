# Корпус распознавания v0 (META-002)

Тестовый корпус для оценки распознавания фильмов, сериалов и аниме в формате [`corpus-record.v1`](../schema/corpus-record.v1.schema.json) (гайд разметки — [GUIDE.md](../GUIDE.md)). По [ADR-0011](../../../docs/adr/0011-maintainer-decisions-release-0-1.md) п. 8 корпус живёт в этом репозитории и содержит **только собственные данные проекта**: ни тест-кейсов guessit/Sonarr/Jellyfin (LGPL/GPL), ни заголовков с приватных трекеров.

| Путь | Что это |
|---|---|
| `v0/train.jsonl`, `v0/dev.jsonl`, `v0/test.jsonl` | сам корпус (сплиты) |
| `gen/titles.yaml` | вручную составленный список реальных публичных работ (фильмы, сериалы, daily-шоу, аниме-франшизы с порядком записей AniDB, аниме-фильмы) |
| `gen/resolve.py` | сверка ID по открытым источникам → `gen/facts.json` |
| `gen/facts.json` | проверенные факты: ID, годы, хронометраж, списки эпизодов (только нужные поля) |
| `gen/generate.py` | детерминированный генератор вариаций имён поверх `titles.yaml` + `facts.json` |
| `gen/tape.py` | офлайн-«кассета» поиска для бейзлайна `pa-eval` |
| `../baselines/v0/` | отчёты бейзлайнов `pa-eval` по корпусу v0 |

## Как устроен

1. **Работы — вручную.** `titles.yaml` перечисляет ~230 фильмов (в т. ч. советские и российские, ремейки и одноимённые, названия с цифрами), ~70 сериалов (в т. ч. российские и одноимённые), 15 daily-шоу, ~90 аниме-записей AniDB, сгруппированных во франшизы (длинные онгоинги, многосезонные, OVA/ONA/спешлы, ремейки), и ~60 аниме-фильмов.
2. **ID — из открытых источников, не из головы.** `resolve.py` находит каждую работу в Wikidata (CC0) и берёт оттуда TMDB, IMDb, TVDB, TVmaze, Кинопоиск, год премьеры, хронометраж и русское название; для сериалов сверяет IMDb/TVDB с TVmaze и берёт оттуда список эпизодов с датами эфира; для аниме берёт AniDB/MAL/AniList/Kitsu, тип и число эпизодов из anime-offline-database (ODbL, релиз `2026-45`, тот же, что в `data/anime-mappings/upstream.env`), а TMDB — из Wikidata по AniDB ID. Неоднозначные и несошедшиеся работы попадают в `problems` и генератором не используются.
3. **Имена — генератором.** `generate.py` строит группы файлов (папка сериала, батч фансаба, BDMV, папка-свалка и т. д.) по шаблонам на каждую категорию A1–A17: группы релизов, CRC32, `v2`, разрешения, источники, разделители, кириллица и транслит, студии озвучки, двойные названия, extras и сэмплы, `cd1/cd2`. Ожидаемый разбор (`parse`) строится из тех же токенов, что записаны в путь, поэтому он верен по построению. Технические поля (`duration_ms`, `size`, видео, языки дорожек) правдоподобны: длительность — из хронометража работы; хэшей нет (синтетические хэши ничего не проверяют).
4. **Детерминизм.** Повторный запуск с теми же `titles.yaml`, `facts.json` и `--seed` даёт побайтно тот же корпус.

```bash
cd tools/recognition-eval/corpus/gen
# 1. (онлайн, по необходимости) пересверить ID; AOD — закреплённый релиз из data/anime-mappings/upstream.env
python3 resolve.py --aod /path/to/anime-offline-database.jsonl --cache /tmp/pa-corpus-cache
# 2. (офлайн) сгенерировать корпус
python3 generate.py
# 3. проверить
cargo run -p pa-recognition-eval --bin corpus-validate -- --min-per-category 50 ../v0/*.jsonl
```

## Статусы: что проверено, а что нет

Ключевой KPI — тихие ошибки, поэтому неверная «истина» хуже отсутствующей (GUIDE §10.1). Статус записи ставится строго:

- **`verified`** — все работы записи не эпизодические (фильмы, аниме-фильмы) или daily-шоу, где эпизод задан датой эфира; все ID получены и сверены `resolve.py`; запись проходит `corpus-validate --strict`.
- **`draft`** — в записи есть позиции эпизодов в схемах, которые нельзя сверить без ключа провайдера:
  - `tmdb` у сериалов взят из эфирного порядка TVmaze (season/number) — для выбранных западных и российских сериалов он совпадает с TMDB, но API TMDB не запрашивался (ключа проекта ещё нет, DEC-008);
  - у аниме номер `anidb` выведен из порядка записей франшизы и числа эпизодов anime-offline-database, а `tmdb` (сезон и смещение) и `tvdb_absolute` — по правилам мейнтейнера в `titles.yaml` (поля `tmdb_season`, `tmdb_offset`, `abs`); TMDB/TVDB не запрашивались.

  В `review.notes` каждой такой записи сказано, какая схема не сверена. Перевод в `verified` — задача META-025 (сверка с TMDB/TVDB, когда появится ключ, и двойная разметка по META-019).

`review.annotators` — псевдоним генератора `pa-meta002`; `double_labelled` не ставится: человеческая двойная разметка 10 % корпуса — META-019.

## Сплиты

Сплит выбирается по хэшу «группы» (франшиза, сериал, фильм или группа ремейков), поэтому вариации одной работы не попадают в разные сплиты: train ≈ 60 %, dev ≈ 20 %, test ≈ 20 %. Репозиторий публичный, поэтому test-сплит открыт; правило то же, что в GUIDE §8: параметры по нему не подбираются, он только для итоговых отчётов. Закрытый сплит появится вместе с данными волонтёров (отдельный репозиторий, ADR-0011 п. 8).

## Лицензия и атрибуция

Записи корпуса, `titles.yaml`, генератор и отчёты — собственные данные проекта под **MPL-2.0** (`source.license: MPL-2.0` в каждой записи, аннотация в `REUSE.toml`). Это синтетические имена файлов, придуманные генератором, и разметка-факты о публичных произведениях.

Факты для разметки сверены с открытыми источниками, которым мы благодарны:

- **Wikidata** (CC0-1.0) — TMDB/IMDb/TVDB/TVmaze/Кинопоиск ID, годы, хронометраж, русские и японские названия.
- **TVmaze** (данные CC BY-SA 4.0) — списки эпизодов и даты эфира, по которым выбраны номера и даты; в корпусе только отдельные факты (номер сезона и эпизода, дата), а не выдержки из базы.
- **anime-offline-database** — *Contains information from anime-offline-database (cedya77, continuation of manami-project), made available under the ODbL v1.0* (<https://github.com/cedya77/anime-offline-database>, <https://github.com/manami-project/anime-offline-database>, <https://opendatacommons.org/licenses/odbl/1-0/>). Из базы взяты AniDB/MAL/AniList/Kitsu ID, тип и число эпизодов для ~150 записей — несущественная выдержка (ODbL §1 «Substantial»), поэтому share-alike на корпус не распространяется, но атрибуция сохраняется здесь и в `gen/facts.json`.

Названия произведений — фактические данные; бренды и логотипы сторонних сервисов в корпус не входят.
