# Бейзлайны `pa-eval` на корпусе v0

Отчёты встроенных распознавателей `pa-eval` (META-003) на [корпусе v0](../../corpus/README.md) (META-002). Это нижняя планка, от которой меряется настоящий пайплайн; бейзлайны внешних систем (guessit, hunch, Jellyfin) — META-004.

| Файл | Что это |
|---|---|
| `abstain.{md,json}` | всё в ручную очередь — проверка раннера, Coverage 0 |
| `naive.{md,json}` | грубый разбор имени + один `tmdb/search`, топ-1, порог авто 0.9 |
| `naive-t080.{md,json}` | то же с порогом 0.8 — показывает, где наивный поиск ошибается молча |
| `parser.{md,json}` | продуктовый парсер имён `pa-recognition` (META-005 + правила META-006) без поиска работы: только метрики парсинга, Coverage 0 |
| `tmdb-search.tape.jsonl` | офлайн-кассета ответов `tmdb/search` |
| `candidates.{md,json}` | META-007: recall@k кандидатов из локального индекса названий на train + dev |
| `candidates-test.{md,json}` | то же на test-сплите (итоговый отчёт, параметры по нему не подбирались) |
| `title-catalog.jsonl` | офлайн-замена кэша TMDB для `candidates`: фильмы и сериалы корпуса с названиями (`corpus/gen/catalog.py`) |
| `scorer.{md,json}` | META-026: скорер v0 (`pa_recognition::score`) поверх того же индекса — работа, запись франшизы и эпизод; train + dev |
| `scorer-test.{md,json}` | то же на test-сплите (один прогон, параметры по нему не подбирались) |

**Кассета — не запись TMDB.** Ключа TMDB у проекта ещё нет (DEC-008), поэтому `corpus/gen/tape.py` отвечает на ровно те запросы, что делает `naive`, поиском по названиям работ корпуса (`facts.json`, `titles.yaml`): точное совпадение после нормализации, фильтр по году, если он передан, иначе — новые работы первыми (грубая замена «популярности» TMDB), в ответе только TMDB/IMDb ID. Поэтому абсолютные числа завышены по сравнению с настоящим TMDB (нет посторонних совпадений), но провалы на ремейках, одноимённых сериалах и сезонах аниме воспроизводятся. Когда появится клиент META-009, кассету нужно перезаписать `RecordingProvider`-ом.

Воспроизведение (офлайн, побайтно):

```bash
CARGO_TARGET_DIR=... tools/recognition-eval/corpus/gen/baselines.sh
```

## Парсер `pa-recognition` (`parser`)

Разбор имён продуктовым парсером, весь корпус. `number` — номер эпизода без учёта схемы: голое `- 35` пишется одинаково, считает ли релизёр внутри сезона или сквозь франшизу, поэтому `episodes` против `absolute` решает матчер по числу эпизодов записей, а не парсер (GUIDE §6). «Строго» — все поля, «номер без схемы» — `number` вместо `episodes`/`absolute`.

## Кандидаты из локального индекса названий (`candidates`, META-007)

`pa-eval candidates` строит `pa_recognition::title::TitleIndex` из локальных данных и для каждого размеченного файла с внешними ID работы проверяет, есть ли эта работа в топ-k кандидатов. Запрос — все названия N-best гипотез парсера `pa-recognition` (плюс год, сезон и тип из лучшей гипотезы). Внешних запросов нет.

Индекс: **встроенная база anime-offline-database** (META-008, релиз `2026-45`, 38 418 аниме с синонимами) и `title-catalog.jsonl` — 306 фильмов, сериалов и daily-шоу корпуса с оригинальным/английским и русским названием, как их держал бы кэш TMDB. Итого 38 724 записи, 220 155 различных названий.

| Срез | Элементов | R@1 | R@3 | R@5 | R@10 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| train + dev | 3 857 | 77,39 % | 95,51 % | 97,04 % | **99,51 %** | 0,8636 |
| test (один прогон) | 927 | 75,19 % | 96,87 % | 98,06 % | **99,35 %** | 0,8539 |
| аниме, train + dev | 2 278 | 67,16 % | 92,89 % | 95,13 % | 99,30 % | 0,7985 |
| A7 (кириллица), train + dev | 656 | 93,60 % | 99,54 % | 99,54 % | 99,54 % | 0,9654 |

Цель META-007 (≥ 90 % верных кандидатов в топ-10 без внешних запросов) выполнена. Параметры подбирались только на train/dev; test прогнан один раз.

Что видно по отчётам:

- **R@1 у аниме низкий по построению** (A2, A3, A16 — единицы процентов): по имени `Gintama - 235` все записи франшизы (`Gintama`, `Gintama'`, `Gintama.`…) совпадают одинаково, выбрать сезон или кусок может только скорер по номерам эпизодов, году и числу эпизодов записи (META-014). Индекс отвечает за то, чтобы нужная запись была в списке: R@10 = 100 % на A1–A3 и A16.
- **Промахи R@10** почти все — extras без названия работы в пути (`Anime/Movies/Extras/Trailer 3.mkv`, `1612 (2007)/sample.mkv`): их работа определяется по соседям в группе, а не по имени файла. Остальные — `Kimetsu no Yaiba/Season 4/…` → запись `Hashira Geiko-hen` на 12-м месте.
- **Ограничение каталога фильмов и сериалов:** в нём только работы корпуса, поэтому конкурентов у фильмов меньше, чем в настоящем кэше TMDB (аниме ищется среди всех 38 тыс. записей). Каталог нужно перезаписать из `pa_metadata::tmdb::titles::title_record`, когда появится ключ TMDB.
- Скорость на сервере сборки (release): построение индекса ~1,5 с, поиск ~2 мс на файл.

Воспроизведение: нужен бандл `data/anime-mappings/dist/anime-offline-ids.jsonl` (`data/anime-mappings/build.sh`, скачивает закреплённый релиз), дальше `baselines.sh` (переменная `AOD_BUNDLE` переопределяет путь; без бандла шаг пропускается).

## Скорер v0 (`scorer`, META-026)

`pa-eval run --recognizer scorer` строит тот же индекс, что `candidates` (anime-offline-database + `title-catalog.jsonl`), и для каждого файла группы выбирает работу модулем `pa_recognition::score`: топ-10 кандидатов по N-best гипотезам парсера → «прочтения» кандидата (тип и год; для аниме — франшиза из TV/ONA-записей с общим базовым ключом названия: номер внутри записи, абсолютный номер через франшизу или по названию `(Episodes 202-252)`, явный сезон → запись, чьи названия его заявляют, перелив номера в следующие записи) → ручные веса → уверенность из лучшего балла и отрыва от другой работы. Ремейки с тем же названием (`Fruits Basket` 2001/2019, `Hunter x Hunter` 1999/2011) без года в имени не уходят в авто. Extras и файлы без названия берут решение папки. Провайдеры не вызываются.

| Срез | Оценено | Precision@auto | Coverage | Тихие ошибки | Проверка |
|---|---:|---:|---:|---:|---:|
| `naive`, порог 0.9 (весь корпус) | 4 784 | 100,00 % | 14,51 % | 0,00 % (0) | 39,36 % |
| `scorer`, train + dev | 3 857 | 100,00 % | **91,57 %** | **0,00 % (0)** | 8,43 % |
| `scorer`, test (один прогон) | 927 | 99,25 % | 85,76 % | 0,65 % (6) | 14,24 % |

На train + dev: аниме 90,6 %, фильмы 94,3 %, сериалы 90,9 % Coverage; A1 100 %, A2 90,0 %, A3 94,0 %, A16 95,7 %, A8 47,3 % (ремейки и одноимённые без года честно уходят на проверку). Запас по порогу: на 0.85 тихих ошибок по-прежнему 0, на 0.8 — 5. Эпизоды в авто-матчах: `anidb` верно в 90,8 %, `tvdb_absolute` — 77,9 %, `tmdb` — 48,5 % (для аниме только порядок «как написано» `SxxEyy`; смещений сезонов TMDB без данных TMDB нет).

Веса и правила подбирались только на train + dev (оба сплита, отдельного отложенного dev не было), поэтому test — честная оценка: Coverage ниже на 6 п. п., тихие ошибки 0,65 % — выше цели 0,5 %. Все 6 — два известных провала, по которым ничего не подкручивалось:

- `Attack on Titan - 38…47` (A1, 5 файлов): абсолютный номер раскладывается по записям AniDB, упорядоченным по году; у Shingeki no Kyojin порядок и разбиение на части в anime-offline-database не совпадают с абсолютной нумерацией релизёров. Нужны маппинги AniDB ↔ TVDB (Anime-Lists, качаются на устройство — META-008/META-015).
- `Koukaku Kidoutai 2.0` (A17): «2.0» в названии фильма — перевыпуск, а не продолжение; без длительности (LIB-006) не отличить.

Ограничения: каталог фильмов и сериалов содержит только работы корпуса (см. `candidates`), а записи аниме — это anime-offline-database без связей между записями, поэтому франшиза восстанавливается эвристикой по названиям и годам. Длительность, языки дорожек, хэши и совместные ограничения по группе (эпизоды уникальны, подряд) — META-014; калибровка уверенности — META-018 (ECE сейчас 0,026 на train + dev).
