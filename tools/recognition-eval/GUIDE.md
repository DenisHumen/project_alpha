# Гайд по разметке корпуса распознавания

> Версия формата: `schema_version: 1`. Задача: META-001. Основание: [`docs/research/03-metadata-recognition.md`](../../docs/research/03-metadata-recognition.md) §1.2, §5, §6.
> Машинная схема — [`schema/corpus-record.v1.schema.json`](schema/corpus-record.v1.schema.json), таксономия — [`schema/taxonomy.v1.json`](schema/taxonomy.v1.json), проверка — `corpus-validate` (см. [README](README.md)).

Корпус нужен, чтобы честно мерить распознавание: точность, покрытие и прежде всего **тихие ошибки** (неверный матч с высокой уверенностью). Поэтому разметка — это «истина», а не мнение пайплайна. Если истину установить нельзя, это тоже ответ (`role: unknown`), а не повод угадывать.

## 1. Единица разметки — кейс

Одна строка JSONL — один **кейс**: дерево файлов, как его увидит сканер (папка сериала, папка фильма с extras, диск, папка-свалка). Внутри кейса:

- `input.files` — **вход** пайплайна: относительные пути и то, что сканер может узнать сам (размер, длительность, языки дорожек, oshash, ed2k, CRC32, теги контейнера). Здесь нет ответов.
- `labels.works` — **работы** (фильм, сериал, аниме-запись), к которым относятся файлы. В одном кейсе может быть несколько работ (A15, фильм в папке сериала).
- `labels.files` — **метка на каждый файл**: роль, ссылка на работу, эпизоды в провайдерских схемах, ожидаемый разбор имени.

Правило полноты: **каждый файл из `input.files` покрыт ровно одной меткой.** Метка дисковой структуры (`unit: bdmv|video_ts`) покрывает все файлы под своим каталогом.

## 2. Пути и приватность

- Пути относительные, в стиле POSIX (`/`), без `.`/`..`, без буквы диска.
- Корень кейса — то, что пользователь добавил как источник, или ближайшая осмысленная папка (`Anime/`, `Movies/`, `Downloads/`). Всё выше отрезается.
- **Никаких личных данных:** домашние каталоги (`home/<user>`, `Users/<user>`), имена пользователей, e-mail, названия компьютеров и шар заменяются или отрезаются. Валидатор ловит самые частые случаи, но ответственность на разметчике.
- Личные видео (`VID_20240101_120000.mp4`, «Новогодний корпоратив.mp4») можно оставлять как негативные примеры с `role: unknown`, но имя не должно раскрывать человека.
- Хэши (`oshash`, `ed2k`, `crc32`) — только от реальных файлов волонтёров или синтетические; синтетические помечаются `source.kind: synthetic`.

## 3. Работа (`labels.works[]`)

| Поле | Правило |
|---|---|
| `ref` | `w1`, `w2`… уникален в кейсе |
| `kind` | `movie` — фильм (не аниме); `show` — сериал (не аниме); `anime` — любое аниме (сериал, OVA, фильм) |
| `anime_type` | только для `anime`: `tv`, `ova`, `ona`, `movie`, `special`, `music_video` — **как в AniDB** |
| `title` | для людей; на скоринг не влияет. Пишется оригинальное или самое узнаваемое название |
| `year` | год премьеры работы (для аниме — год выхода этой AniDB-записи) |
| `ids` | внешние ID. Канонический: для `movie`/`show` — `tmdb`, для `anime` — `anidb`. Остальные (`tvdb`, `imdb`, `anilist`, `mal`, `shikimori`, `kinopoisk`, `tvmaze`, `kitsu`) — по возможности |
| `display_scheme` | необязательно: схема, в которой пользователь ожидал бы видеть серию |

Форматы ID: `tmdb` — `movie:27205`, `tv:1399`, `collection:…`; `tvdb` — `series:…`/`movie:…`; `imdb` — `tt0133093`; остальные — целые числа.

**Граница работы для аниме — запись AniDB.** Если AniDB делит франшизу на куски (второй сезон, «The Final Season Part 2», OVA), каждый кусок — отдельная работа, даже если в TMDB это сезон одной серии (A2). TMDB-ID при этом указывает на общую серию (`tv:1429`), а связь куска с её сезоном выражается нумерацией эпизодов (§5).

## 4. Метка файла (`labels.files[]`)

| `role` | Когда | Обязательно | Запрещено |
|---|---|---|---|
| `main` | основной файл фильма или эпизода | `work`; `episodes` для эпизодических работ | `part`, `extra_type` |
| `part` | кусок разбитого фильма или эпизода (`cd1`, `part2`, `disc1`) — A13 | `work`, `part` (1..N без пропусков, N ≥ 2) | `extra_type` |
| `extra` | трейлер, featurette, NCOP/NCED, меню, превью — A10 | `extra_type`; `work`, если понятно, к чему относится | `part` |
| `sample` | `sample.mkv` и подобные обрезки релиза | — | `episodes` |
| `sidecar` | `.nfo`, `.srt`, `.ass`, картинки, `.txt` | — | `episodes` |
| `ignore` | мусор и обрезки, которые не должны попасть в медиатеку | — | `work`, `episodes` |
| `unknown` | видео, которое невозможно опознать (личное, неизвестный рип) — правильный ответ: «в ручную очередь» | — | `work`, `episodes` |

Дополнительно:

- `unit` — `file` (по умолчанию), `bdmv` или `video_ts`. Для дисковой структуры (A12) метка ставится на **каталог, содержащий** `BDMV/` или `VIDEO_TS/`, например `Movies/Inception (2010)`. ISO — обычный файл (`unit: file`).
- `edition` — `theatrical`, `directors_cut`, `extended`, `unrated`, `uncut`, `remastered`, `imax`, `special_edition`, `final_cut`, `other`.
- `extra_type` — `trailer`, `teaser`, `featurette`, `behind_the_scenes`, `deleted_scene`, `interview`, `short`, `scene`, `opening`, `ending`, `menu`, `preview`, `other`.
- `notes` — короткое объяснение для спорных решений. Если решение принято по правилу этого гайда, сослаться на пункт.

## 5. Эпизоды и схемы нумерации

`episodes` — массив: один элемент на эпизод, мульти-эпизодный файл (A9) содержит несколько.

```json
{ "type": "regular",
  "numbering": {
    "anidb":         { "type": "regular", "number": 6 },
    "tmdb":          { "season": 2, "episode": 6 },
    "tvdb_aired":    { "season": 2, "episode": 6 },
    "tvdb_dvd":      { "season": 2, "episode": 6 },
    "tvdb_absolute": 30,
    "tmdb_group":    { "group_id": "<24 hex>", "season": 1, "episode": 30 } },
  "air_date": "2023-08-03" }
```

- `type` — тип эпизода по модели данных (03 §5): `regular`, `special`, `credit` (OP/ED), `trailer`, `parody`, `other`, `recap`.
- `numbering.anidb.type` — тип эпизода **в AniDB** и должен совпадать с `type`; исключение — `recap`, который в AniDB бывает и `regular`, и `special`.
- **Минимум две схемы для аниме:** `anidb` + хотя бы одна из `tmdb`/`tvdb_*`/`tmdb_group`. Исключение — `credit`, `trailer`, `parody`: у TMDB/TVDB их нет.
- Для `show` обязательна `tmdb` (или `tmdb_group`); `tvdb_*` — если известны и отличаются от TMDB (A16).
- **Daily shows (A11):** обязателен `air_date`; `numbering` можно не указывать.
- Номера — **провайдерские**, а не «как в имени файла». «Как в имени» пишется в `parse` (§6).
- OVA, которые в AniDB — отдельная запись: эпизод `regular` в этой записи и, как правило, `tmdb` season 0 общей серии. Это нормально.
- `.5`-эпизоды и рекапы: тип по AniDB (обычно `special`/`recap`), в TMDB — тот эпизод, куда их положил TMDB (часто season 0). Не «S00 наугад»: если не нашли — оставить только известную схему и описать в `notes`.

## 6. Ожидаемый разбор имени (`parse`)

Необязательный блок для метрик парсера (03 §6.2 «Парсинг»). Пишется то, что **написано в имени и пути**, а не то, что знает провайдер.

| Поле | Пример |
|---|---|
| `title` | `Shingeki no Kyojin - The Final Season`, `1917`, `9-1-1`, `Steins;Gate 0` |
| `alt_titles` | второе название двойного имени: `The Master and Margarita`; название из папки на другом языке |
| `year`, `season`, `episodes`, `absolute` | как в имени; дробные эпизоды допустимы: `[18.5]` |
| `episode_kind` | `ncop`, `nced`, `ova`, `ona`, `sp`, `recap`, `special`, `regular` |
| `date` | дата в имени daily-шоу |
| `part` | номер куска (`cd2` → 2) или «Part 2» в названии сезона |
| `release_group`, `crc32`, `version` | `SubsPlease`, `ABCD1234`, `2` для `01v2` |
| `dub_studio` | студия озвучки/трекер: `LostFilm`, `AniLibria` |
| `resolution`, `source`, `edition`, `languages` | `1080p`, `BDRip`, `Director's Cut`, `["rus","eng"]` |

Правила: CRC32 пишется заглавными; группа — без скобок; `title` — без мусорных токенов, без года и номеров, но с цифрами, которые входят в название (A14). Транслит не исправляется: `Ironiya sudby` остаётся как есть, кириллическое название идёт в `alt_titles`. Квалификаторы записи в аниме-именах перед ` - NN` (`2nd Season`, `Season 2`, `Part 2`, `OVA`, год в скобках `(2011)`) остаются в `title`: так называется запись AniDB (`Boku no Hero Academia 3rd Season - 04` → `title: Boku no Hero Academia 3rd Season`); `season`, `part`, `episode_kind` при этом можно заполнить. Короткая метка `S2` — не часть названия. Голый номер `- 35` размечается в `absolute`, если релизёр считает сквозь сезоны франшизы, иначе в `episodes`; по одному имени это не различить, поэтому `pa-eval` дополнительно считает поле `number` — номер без учёта схемы (META-006).

## 7. Категории A1–A17

Коды и краткие описания — в [`schema/taxonomy.v1.json`](schema/taxonomy.v1.json) (источник — 03 §1.2). Первая категория в `categories` — **основная** (для стратификации), остальные — дополнительные. Ставить все категории, которые кейс действительно проверяет.

Каждая категория обещает, что кейс содержит её трудный случай; валидатор это проверяет:

| Код | Что должно быть в разметке |
|---|---|
| A1 | `parse.absolute` хотя бы у одного файла |
| A3 | эпизод в двух и более схемах |
| A4 | не-`regular` эпизод, extra `opening`/`ending` или работа `ova`/`ona`/`special` |
| A5 | разные названия у файлов, `parse.alt_titles` или несколько работ |
| A6 | `parse.release_group` или `parse.crc32` |
| A9 | файл с ≥ 2 эпизодами |
| A10 | `extra` или `sample` |
| A11 | `air_date` у всех эпизодов |
| A12 | `unit: bdmv|video_ts` или `.iso` |
| A13 | файлы с `role: part` |
| A14 | `parse.title` |
| A15 | ≥ 2 работ |
| A16 | эпизод в ≥ 2 порядках TMDB/TVDB |
| A17 | работа `anime` с `anime_type: movie` |

Для A2, A7, A8 формальных требований нет: категория ставится по смыслу (сезон как отдельный тайтл, кириллица/русский релиз, нет года или есть одноимённые работы).

## 8. Источник, сплит, статус

- `source.kind`: `synthetic` (придумано), `release_feed` (заголовки RSS/предб), `volunteer_library` (дамп библиотеки), `eval_suite` (тест-кейсы чужих парсеров), `issue_report` (кейс из issue/форума), `manual`.
- `source.license` — SPDX-лицензия **содержимого записи**. Кейсы из guessit (LGPL-3.0), Sonarr (GPL-3.0), Jellyfin (GPL-2.0) хранятся **только в eval-репозитории** и только как данные для оценки; в репозиторий продукта не попадают (валидатор запрещает GPL/LGPL для `split: example`). Наши собственные примеры — `MPL-2.0`.
- `split`: `train`, `dev`, `test` (закрытый: только финальные отчёты, параметры по нему не подбираются), `example` (иллюстрации формата в этом репозитории).
- `review.status`: `draft` — предразметка или неполная разметка (недостающие ID и схемы — предупреждения); `verified` — проверено человеком, **любое предупреждение становится ошибкой**; `disputed` — спор, ждёт арбитра.
- `review.annotators` — только псевдонимы. `double_labelled: true` требует ≥ 2 разметчиков (10 % корпуса размечается дважды, согласие — Cohen's κ, цель ≥ 0.8).

## 9. Процесс разметки

1. Предразметка пайплайном (и FileBot/Shoko для аниме, если доступны) → `status: draft`.
2. Разметчик проверяет каждую работу по сайту провайдера: ID, год, тип, число эпизодов, длительность.
3. Нумерация: сначала каноническая схема (AniDB для аниме, TMDB для остального), затем остальные — по Anime-Lists, TMDB episode groups, TVDB.
4. `corpus-validate --strict` без ошибок → `status: verified`.
5. Спорный случай → `disputed` + `notes`; арбитр решает и **дописывает правило в этот гайд** (раздел 10), чтобы следующий такой случай размечался одинаково.

## 10. Правила для спорных случаев

1. **Не уверен — не угадывай.** Лучше `unknown` или пустая схема с `notes`, чем правдоподобная, но неверная разметка: неверная истина портит главный KPI.
2. Фильм в папке сериала (A17) — отдельная работа, а не эпизод.
3. Несколько версий одного эпизода (`v1` и `v2`) — обе `main` с одинаковыми эпизодами (валидатор выдаст предупреждение). Если релиз явно заменён (`v1` рядом с `v2` той же группы) — старый `ignore`.
4. Мусорный обрывок рипа (минута, нет смысла) — `ignore`, а не `part`.
5. `Part Two` в названии фильма («Dune: Part Two») — часть названия, а не `part`.
6. TV-перемонтаж фильма (или наоборот) — разные работы, даже если сюжет один.
7. Если релизёр пронумеровал по одной схеме, а файлы реально соответствуют другой (DVD vs эфир, A16), истина — **реальное содержимое** (сверка по длительности и названию эпизода), а «как в имени» — в `parse`.
8. Двойные названия через `/` в имени файла невозможны; в путях встречается `∕` (U+2215) или `|`. Разметчик не нормализует путь — он вход.

## 11. Версионирование формата

- Несовместимое изменение схемы → новый файл `corpus-record.v2.schema.json` и `schema_version: 2`; валидатор поддерживает старые версии, пока они есть в корпусе.
- Новая категория → добавить в `taxonomy.v1.json` (коды не переиспользуются) и при необходимости требование в валидатор.
