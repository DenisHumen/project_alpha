# Правила проекта project_alpha

> Общие инструкции для любых AI-агентов (как взять задачу, команды проверки, запреты) — в [AGENTS.md](AGENTS.md); в `core/`, `clients/flutter/`, `clients/apple/`, `server/`, `distro/` есть свои `AGENTS.md` с командами области. Ниже — правила владельца, они имеют приоритет, и заметки для Claude Code.

## Правила владельца

- Язык общения и документации — русский; код, идентификаторы и коммиты — на английском (Conventional Commits).
- Разработка идёт с нескольких ПК: перед началом работы `git pull`, после каждого заметного шага — коммит и `git push`. Репозиторий должен всегда быть актуальным.
- Проект open source, всё работает локально у пользователя — никаких наших серверов/облака; деньги — добровольные пожертвования (см. `docs/STRATEGY.md` v2).
- Один публичный репозиторий `DenisHumen/project_alpha` (MPL-2.0): код, документация, сборки в GitHub Releases. Принимаем внешние PR — см. CONTRIBUTING.md.
- Работа по задачам из `docs/ROADMAP.md`: одна задача = одна ветка `feat/<ID>-slug` в своём worktree, коммиты с `git commit -s` (DCO), PR с `[<ID>]` в заголовке, галочка в ROADMAP в том же PR. Не брать задачу, пока открыты её зависимости.
- Репозиторий публичный: никаких секретов, личных данных, путей и email владельца в коде и документах.
- Стратегия и решения: `docs/STRATEGY.md`; исследования: `docs/research/`; решения по архитектуре оформлять как ADR в `docs/adr/`.
- Не использовать бренд, логотипы и ассеты Infuse/Firecore, Fedora, Dolby/DTS без лицензии.
- FFmpeg/mpv — только LGPL-сборки; GPL-код в клиенты не добавлять.
- Секреты не коммитить: `.env.local` (в .gitignore), шаблон — `.env.example`. Политика — `docs/dev/secrets.md`.

## Заметки для Claude Code

- В начале сессии прочитать `docs/STATUS.md` (текущее состояние и приоритет) и `AGENTS.md`.
- Параллельные агенты работают в своих worktree (`.claude/worktrees/…`): не трогать чужие ветки и worktree, не делать `git stash` без уникальной метки (стек общий), не ставить git-хуки в общий `.git` (`pre-commit install` — только в своём клоне).
- Сообщение коммита заканчивается трейлером `Co-Authored-By` агента; `Signed-off-by` (`git commit -s`) обязателен.
- На общей машине — `nice` и не больше `-j4`; инструменты ставить локально для пользователя, без sudo.
- В PR честно разделять «проверено» и «не проверено»; решения, которые принадлежат владельцу, выносить в раздел PR «Решения владельца», а не принимать самостоятельно.
